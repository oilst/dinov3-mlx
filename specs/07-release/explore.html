Step 7 Release: Explore

Roadmap step 7. Status: options picked. On 2026-11-09 the user took all recommendations (Table 9). All questions are answered. Date: 2026-11-09.

1 What Step 7 must do and the starting point

Roadmap row 7: a Python API, a README with the results, CI and the first public push. Section "Step 7" of docs/plan.html gives five actions: write the public API embed_frames and embed_patches, write the README, add a GitHub Actions workflow for the tests that need no weights, ask the user to approve the license, the name and the first push, then create the public repo and push. The step ends when the repo is public, CI passes and the README shows the results.

These points are fixed. They are not options:

  • The code is MIT, the weights stay under the DINOv3 License, and the repo never holds weights (ADR 0002). ADR 0002 asks for a legal check before the first push.
  • The API runs the compiled forward pass (ADR 0010). The fp32 dtype mode runs with TF32 off (ADR 0005). The parity thresholds of ADR 0003 do not change.
  • The README states the limits of the Step 6 results: one paired round does not decide the matrix cells near 1 (V17), the throughput drifts between jobs (V2), and the best batch size rests on one round (V4).
  • Step 7b adds the Neural Engine backend later, behind the same API. mlx stays the default backend.
  • Every push and every change on GitHub is an external action. The agent does each one only after the user says yes.

2.6 The name

  • On PyPI the names dinov3-apple, dinov3-mlx, mlx-dinov3 and dinov3 are free (HTTP 404 on 2026-11-09).
  • On GitHub these DINOv3 ports have similar names: vincentamato/MLXDINOv3, sarveshmayil/mlx-dinov3 and etornam45/mlx_dinov3.
  • Apple's "Guidelines for Using Apple Trademarks and Copyrights" do not let a third party use an Apple trademark as a part of a product name. A phrase such as "for Apple silicon" in the description is a different case. This is not a legal opinion.
  • The DINOv3 License has no rule for names. It asks for an acknowledgment in publications (clause 1.b.ii).
  • A rename touches 128 files (927 lines) with dinov3_apple, 41 files (80 lines) with dinov3-apple, and the folder ~/.cache/dinov3-apple/ (converted weights, Core ML packages, GPU lock).

3 Decisions and options

3.1 D1: the form of the API

  • Option A, functions only. embed_frames(frames, model_size=...) and embed_patches(...). A hidden cache keeps the last model. The plan names these two functions.
  • Option B, an object with methods. The object loads and compiles once and holds the model and the compiled forward pass. Its methods are embed_frames, embed_patches and embed (both outputs from one forward pass).
  • Option C, a Hugging Face form. Dinov3Model.from_pretrained("facebook/dinov3-vits16-pretrain-lvd1689m") and a call that returns all tokens.
import numpy as np
from dinov3_mlx import Embedder          # name: D4

model = Embedder("ViT-S/16")             # default dtype mode (D2c), compiled forward pass
frames = np.stack(rgb_frames)            # uint8, (B, h, w, 3), one size
frame = model.embed_frames(frames)       # (B, 384) fp32
patches = model.embed_patches(frames)    # (B, 14, 14, 384)
frame, patches = model.embed(frames)     # one forward pass for both

3.3 D3: package dependencies and version pins

  • Option A, as now. torch and transformers are required. Each package is pinned with ==.
  • Option B, a small core. The required packages are only the ones of the API path: mlx, numpy, safetensors, huggingface_hub and pillow. torch and transformers go into an extra reference and into the dev group, for the reference outputs, the baseline and the tests. The core packages get a range, for example mlx>=0.32.4,<0.33. uv.lock keeps the exact versions for this repo.

Trade-off: A installs torch for every user, and exact pins in a library clash with the pins of the user's project. B needs a test that imports the API without torch. With B, users can get an mlx version that we did not measure; the README names the tested versions, and the fingerprint test of each release check shows a change on this Mac. Recommendation: B.

3.4 D4: the name

  • Option A, keep dinov3-apple. No work. The name has an Apple trademark in it (Section 2.6).
  • Option B, rename to dinov3-mlx (import name dinov3_mlx, repo name, cache folder ~/.cache/dinov3-mlx/). A mechanical rename with tests. The local folder of the cache is moved, so no package is converted again. The name is close to the three ports of Section 2.6.
  • Option C, another name of the user's choice.

Recommendation: B. The README says "for Apple silicon" in its description. The legal check (gate G1) covers the name too.

3.5 D5: where users get the package

  • Option A, GitHub only. A tag v0.1.0 and a GitHub release. Install with uv add git+https://github.com/<owner>/<name>@v0.1.0.
  • Option B, GitHub and PyPI. Also a PyPI release through trusted publishing. It needs a PyPI account of the user and a publish workflow, and the name is taken for good.

Recommendation: A. PyPI can follow when the API is stable, for example after Step 7b.
