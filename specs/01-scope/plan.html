1 Goal

Step 1 gives every later step a fixed scope, a license, a Python project and local access to the weights of all six model sizes. The user decided two items on 2026-11-06:

  • Scope: Option A of explore.html. We build our own Python MLX package from the Hugging Face code and the paper. The README leads with the gaps G1 to G7.
  • License: our code under MIT, the weights under the DINOv3 License, a legal check before the first push. docs/adr/0002-mit-for-code-dinov3-license-for-weights.md records the decision.

The rest of this plan creates the Python project and downloads the weights.

2 DINOv3 topic

The topic is what the other ports cover. The explainer docs/learn/01-prior-ports.html puts the four MLX ports next to the Hugging Face code, part by part: the token layout, the 2D RoPE, the feed-forward network, the weight names and the two outputs. It also shows the file sizes of the six model sizes, which set the memory budget of the later steps.

3.2 Weights

The module dinov3_mlx/hub.py holds the six Hugging Face ids of tech-stack.md and two functions: one checks the free disk, one downloads one model size. The script scripts/download_weights.py calls them for each model size, one at a time, from the smallest to the largest. It downloads only config.json, the safetensors files and the safetensors index. The weights go into the Hugging Face cache, outside the repo.

Before each download, the script reads the file sizes from the Hub. It stops if the free disk after the download is less than 50 GB. A download does not load the weights into memory, so the out-of-memory rule of CLAUDE.md does not apply. We still run one download at a time.

3.3 Converted weights while the access waits

On 2026-11-06 the token works, but Meta has not yet approved the access to the gated repos. This Mac holds the Meta checkpoints of ViT-S/16 and ViT-H+/16 (.pth files in the torch hub cache). The script scripts/convert_meta_checkpoint.py converts one checkpoint into a Hugging Face model folder. It adapts the Hugging Face converter convert_dinov3_vit_to_hf.py (Apache-2.0), as ADR 0002 requires.

  1. It checks the SHA-256 of the checkpoint against the 8 hex digits in the file name.
  2. It renames the keys, splits each qkv weight into q, k and v, and loads the result into DINOv3ViTModel with strict=True.
  3. It compares the first 5 values of the frame embedding and of the first patch embedding of one COCO image with the values of the Hugging Face converter (tolerance 1e-3).
  4. It saves the folder to ~/.cache/dinov3-mlx/converted/<Hugging Face id>. It does not write into the Hugging Face cache, so that the real downloads stay clean.

When the access comes, test 9 compares each converted tensor with the downloaded tensor.

def check_free_disk(required_bytes: int, keep_free_bytes: int, path: Path) -> None:
    """Raise InsufficientDiskError if the download leaves less than keep_free_bytes."""
    free = shutil.disk_usage(path).free
    if free - required_bytes < keep_free_bytes:
        raise InsufficientDiskError(f"{free=} {required_bytes=} {keep_free_bytes=}")


def download(model_id: str) -> Path:
    """Download one model size into the Hugging Face cache and return the snapshot path."""
    return Path(snapshot_download(model_id, allow_patterns=WEIGHT_PATTERNS))

6 Tests

  1. test_mlx_default_device_is_gpu: MLX runs on the GPU.
  2. test_torch_mps_is_available: PyTorch can use the MPS backend.
  3. test_transformers_has_dinov3_vit_model: from transformers import DINOv3ViTModel works.
  4. test_model_ids_cover_six_model_sizes: MODEL_IDS holds the six ids of tech-stack.md.
  5. test_check_free_disk_raises_when_space_is_too_small and test_check_free_disk_passes_when_space_is_enough: the disk check stops a download that leaves too little space, and only such a download.
  6. test_weights_are_in_cache[model size]: for each model size, the cache holds config.json and every safetensors file of the index. The test skips with a reason when a model size is missing, so that uv run pytest passes on a machine without weights. verify.html counts the skips.
  7. test_convert_state_dict_splits_qkv_and_renames_keys: the key map and the qkv split of Section 3.3.
  8. test_check_checksum_accepts_matching_name and test_check_checksum_rejects_other_content: the checksum check.
  9. test_converted_weights_match_hub[model size]: each converted tensor is equal to the tensor of the Hub file. The test skips when one of the two files is missing.
