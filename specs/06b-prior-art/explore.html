1 What Step 6b must do and the starting point

Step 6b measures the related public repos with our harness: frame throughput and parity at the same model size, input resolution and batch size. The DINOv3 topic: which parts of the backbone each port changes, and what that costs in parity. Step 1 read the code of four MLX ports but did not run them (specs/01-scope/explore.html, docs/learn/01-prior-ports.html).

The starting point is the Step 6 result. Our compiled forward pass on mlx is about as fast as torch.compile on torch-mps. Paired speedups at P1 (ViT-S/16, 224 px, batch size 8): fp32 1.07, fp16-cast 0.87, bf16-cast 0.88. At P2 (ViT-H+/16, 512 px, batch size 8): 1.01 to 1.09 (results/speedup-table.md).

These points are fixed. They are not options:

  • The parity thresholds of ADR 0003 and the paired measurement of ADR 0004: each row of another repo runs in the same session as a row of our compiled forward pass, in alternation.
  • The run rules of CLAUDE.md: one heavy job at a time through the GPU lock, a memory check before each load, mx.set_memory_limit.
  • The rules for third-party code: each clone or download in its own folder outside the repo (~/.cache/dinov3-mlx/prior-art/), with its own venv; no third-party package in pyproject.toml or uv.lock; Python with -I; no pickle file from a third party; read each file before it runs.
  • Step 6c makes our own Core ML conversion. Step 6b measures only Core ML exports that other people made.
  • New code goes into new files. ADR numbers 0012 and 0013 are for Step 6b.

The permission system refused the run of third-party Python code. At 22:29 on 2026-11-07 the permission system of this session (auto mode) refused the first probe of the two Python MLX ports, with the reason "Code from External". The Explore did not try a workaround. The Core ML probes ran: Apple's coremltools runs downloaded model files with our own probe script. So Section 2 has measured results for the Core ML exports, and code-reading results for the MLX ports. Decision D2 and question Q1 (Section 6) handle the block.

7 New terms

  • Core ML export: a Core ML model package (.mlpackage) of a DINOv3 or DINOv2 backbone that another party made and published.
  • Compute units: the Core ML setting that selects the devices of a model: ALL, CPU_AND_GPU, CPU_AND_NE or CPU_ONLY.
  • Spec-array input: the image input of a Core ML export, changed in the loaded spec to a FLOAT32 multiArray, so the stored pixels go in without 8-bit rounding.
  • Port change: one difference between a port and the Hugging Face backbone, for example bf16 RoPE tables.
  • Port-change variant: our backbone with one port change, to measure the cost of that change in parity and speed.
  • Prior-art ratio: our throughput divided by the throughput of a port or a Core ML export in the same round. Above 1: ours is faster.
