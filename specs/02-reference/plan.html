Step 2 Reference: Plan

Roadmap step 2. Status: approved by the user on 2026-11-06. Date: 2026-11-06.

1 Goal

Step 2 makes the reference output of all six model sizes and the parity tests for torch-mps. Steps 4 and 5 run the same parity tests on mlx. On 2026-11-06 the user chose the recommended option of each decision in explore.html:

  1. D1: three public-domain photos at 16:9, 4:3 and 3:4, in the repo.
  2. D2: float resize with antialiasing in torch. The normalized pixel tensor is stored, and every backend reads it.
  3. D3: 224, 448 and 512 px square, plus the own aspect ratio of each image with a short side of 224 px. 12 configurations for each model size.
  4. D4: safetensors. One input file, one reference file for each model size, all tokens, hidden states for one configuration.
  5. D5: fp16 and bf16 on torch-mps in cast mode and in autocast mode.
  6. D6: patch thresholds on the mean and the 1st percentile. The report also gives the minimum.
  7. D7: the ViT-7B/16 reference in fp32 on torch-cpu, alone and last, after a memory check. ViT-7B/16 on torch-mps in cast mode only.

All six model sizes are in the Hugging Face cache since 2026-11-06. The converted weights of ViT-S/16 and ViT-H+/16 stay as a fallback.

2 DINOv3 topic

The topic is the tokens and the two outputs: the CLS token, the 4 register tokens, the patch tokens, the final layer norm, the frame embedding and the patch embeddings. The explainer docs/learn/02-tokens-and-outputs.html shows the token sequence for each input resolution of D3, the slices that give the two outputs, and the large values of the register tokens inside the backbone (Figure 1 of explore.html). It uses the stored hidden states of Section 3.4 for all six model sizes, so it shows if the other model sizes also have large register values.

Table 4. Stored files. {slug} is the part of the Hugging Face id between dinov3- and -pretrain, for example vith16plus. N is the number of patches, D the embedding dimension, L the number of blocks. Row 0 of hidden_states is the token sequence before block 1.

The header metadata of each file holds one JSON string with: the versions of Python, torch, transformers, safetensors and Pillow; the SHA-256 of each test image; the preprocessing settings; for a reference file also the model size, the weight source (Hugging Face cache or converted folder), the SHA-256 of each weight file, the attention implementation, the run time and the peak memory; and the date.

3.5 Run rules for the reference runs

  1. make_reference.py writes inputs.safetensors first. This needs no model.
  2. For each model size, from the smallest to the largest, it checks the free memory and then starts one subprocess. The next subprocess starts after the previous one ends.
  3. The memory check needs 1.2 × the fp32 weight bytes + 4 GB. The first run measures the peak memory of ViT-S/16 and ViT-H+/16 (resource.getrusage). If the ratio of peak memory to weight bytes is above 1.2, the script uses the measured ratio.
  4. ViT-7B/16 needs about 36 GB by this rule. If the check fails, the script skips ViT-7B/16 and records the reason. The user can then close apps and run make_reference.py ViT-7B/16 again.

Change on 2026-11-06 by the user: bf16 has its own column. The build measured 5 bf16 configurations below the first proposal (0.999, 0.999 and 0.99, the values of the fp16 column). A probe showed that torch-cpu in bf16 gives the same values, so the cause is bf16 arithmetic, not torch-mps. ViT-H+/16 at 224 px is sensitive to its input: fp32 with only the pixels rounded to bf16 gives a patch 1st percentile of 0.9925. The bf16 column takes the worst measured values, rounded down. fp32 and fp16 keep the first proposal.

Rule for a changed threshold. If a measured torch-mps value fails a threshold of Table 6, the build stops and asks the user. The build never lowers a threshold alone. verify.html confirms each threshold or gives the reason for its change. In the Close stage, Table 9 of docs/plan.html and the parity row of mission.md get the final values.

# src/dinov3_apple/hub.py
def weights_dir(model_size: str) -> Path:
    """Return the folder with config.json and the safetensors files of one model size.

    The Hugging Face cache comes first, the converted folder second.

    Raises:
        WeightsNotFoundError: If neither place has all weight files.
    """
    model_id = MODEL_IDS[model_size]
    config = try_to_load_from_cache(model_id, "config.json")
    if isinstance(config, str) and _has_all_weight_files(model_id):
        return Path(config).parent
    converted = CONVERTED_DIR / model_id
    if (converted / "config.json").exists() and any(converted.glob("*.safetensors")):
        return converted
    raise WeightsNotFoundError(f"{model_size}: not in the Hugging Face cache or in {converted}")
# src/dinov3_apple/preprocess.py
def preprocess(image: np.ndarray, size: tuple[int, int]) -> torch.Tensor:
    """Return a normalized (1, 3, H, W) fp32 tensor from an (h, w, 3) uint8 RGB image.

    The resize works on float pixels with antialiasing, as the Hugging Face image processor does.
    """
    pixels = torch.from_numpy(image).permute(2, 0, 1).unsqueeze(0).to(torch.float32) / 255.0
    resized = F.interpolate(pixels, size=size, mode="bilinear", antialias=True)
    return (resized - IMAGENET_MEAN.view(1, 3, 1, 1)) / IMAGENET_STD.view(1, 3, 1, 1)

# src/dinov3_apple/parity.py (NumPy only)
@dataclass(frozen=True)
class Parity:
    frame: float
    patch_mean: float
    patch_p01: float
    patch_min: float


def measure_parity(reference: np.ndarray, output: np.ndarray) -> Parity:
    """Compare two token sequences of shape (1 + 4 + N, D) in fp32."""
    ref, out = reference.astype(np.float64), output.astype(np.float64)
    cos = (ref * out).sum(-1) / (np.linalg.norm(ref, axis=-1) * np.linalg.norm(out, axis=-1))
    patches = cos[NUM_PREFIX_TOKENS:]
    return Parity(cos[0], patches.mean(), np.quantile(patches, 0.01), patches.min())

Change on 2026-11-06 by the user: preprocess resizes and normalizes in fp64 and casts the result to fp32. The fp32 resize of torch was up to 2.2e-5 per pixel away from an fp64 resize on the test images, and failed the 1e-5 limit of AC2. Pillow float resize is within 8e-8 of the fp64 resize. The stored pixels differ from the Hugging Face image processor (fp32) by about 2e-5. An 8-bit resize differs by 0.004.

The cosine runs in fp64. Then two equal fp32 vectors give 1.000000, not 0.9999996 (Table 3 of explore.html).

# tests/test_parity.py (shape)
@pytest.mark.parametrize("model_size", MODEL_SIZES_UNDER_TEST)
@pytest.mark.parametrize("dtype_mode", DTYPE_MODES)
@pytest.mark.parametrize("config", CONFIG_IDS)           # for example "forest/224x304"
def test_parity(model_size, dtype_mode, config, mps_backbone, reference, inputs, record):
    tokens = run_torch(mps_backbone(model_size, dtype_mode), inputs[config], dtype_mode)
    if not np.isfinite(tokens).all():
        record(model_size, dtype_mode, config, None)
        if dtype_mode == "fp16-cast":
            pytest.xfail("fp16 overflow: a register token is above 65,504 (explore.html, Table 2)")
        pytest.fail("non-finite output")
    parity = measure_parity(reference(model_size)[config], tokens)
    record(model_size, dtype_mode, config, parity)
    assert parity.frame >= THRESHOLDS[dtype_mode].frame
    assert parity.patch_mean >= THRESHOLDS[dtype_mode].patch_mean
    assert parity.patch_p01 >= THRESHOLDS[dtype_mode].patch_p01

The fixture mps_backbone keeps one model in memory at a time. It frees the previous model (del, gc.collect, torch.mps.empty_cache) and calls check_free_memory before each load. conftest.py sets the MPS watermarks before torch is imported. record appends one JSON line to tests/fixtures/generated/parity/torch-mps.jsonl.

6 Tests

Each test is written first and must fail first (red). Tests that need weights or stored files skip with a reason when these are missing. ViT-S/16 and ViT-B/16 run by default. The other four model sizes run when DINOV3_SLOW=1 (Table 9 of docs/plan.html).

  1. test_weights_dir_prefers_hugging_face_cache, test_weights_dir_falls_back_to_converted_folder, test_weights_dir_raises_when_no_weights: the order of Section 3.3, with a temporary cache folder.
  2. test_check_free_memory_raises_when_memory_is_too_small, test_check_free_memory_passes_when_memory_is_enough, test_available_memory_is_positive_and_below_total.
  3. test_own_aspect_size: (576, 1024) gives (224, 400), (768, 1024) gives (224, 304), (1024, 768) gives (304, 224), a square gives (224, 224).
  4. test_preprocess_shape_and_dtype: (1, 3, H, W), fp32.
  5. test_preprocess_matches_pillow_float_resize: the largest difference to the Pillow float resize (mode F) is 1e-5 or less in [0, 1] pixel units.
  6. test_preprocess_matches_stored_pixels: preprocess gives exactly the stored pixels of all 12 image and input resolution pairs (largest difference 0.0).
  7. test_test_images_match_sources: the three files exist, have the sizes of Table 1, and their SHA-256 values equal the values in SOURCES.md.
  8. test_split_tokens_drops_register_tokens: with a synthetic sequence, the frame embedding is row 0 and the patch embeddings are rows 5 to 5 + N, reshaped to (H/16, W/16, D). This replaces test_shapes and test_no_register_tokens of Table 9.
  9. test_measure_parity_worked_example: the example of Table 10 of docs/plan.html gives 0.9997. Two equal vectors give 1.0. The 1st percentile of a known list is correct.
  10. test_reference_files_are_complete[model size]: 12 token tensors with shape (1 + 4 + N, D), one hidden-state tensor with shape (L + 1, 201, D), all finite, fp32, and metadata with all fields of Section 3.4.
  11. test_reference_is_reproducible[model size]: a new torch-cpu fp32 run of iss-kibo-lab/224x224 gives the stored tokens with a largest difference of 1e-5 or less.
  12. test_parity[model size, dtype mode, configuration]: Section 5, thresholds of Table 6. 6 model sizes × 12 configurations × 5 dtype modes, minus the 36 ViT-7B/16 skips of Table 5: 324 tests.
  13. test_batch_consistency[model size, dtype mode]: a batch of 8 at 224 × 224 px (the three images, repeated) gives the same outputs as 8 runs with batch size 1. Thresholds: the frame and patch thresholds of the dtype mode.

7 Benchmarks

Step 2 has no throughput benchmark. verify.html records for each model size: the run time of make_reference.py, the peak memory of its subprocess, the free memory before the load, and the run time of the parity tests (default run and DINOV3_SLOW=1).
