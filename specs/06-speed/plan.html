2 DINOv3 topic

The topic of Step 6 is the cost of the forward pass and how the input resolution and the batch size change it. It has four parts.

  • Attention cost at high input resolution. One image gives T = 5 + (side / 16)² tokens. The FLOPs of the attention scores (SDPA) grow as T², the other FLOPs grow as T. So the SDPA share grows with the input resolution and falls with the embedding dimension (Table 4). The MLX SDPA kernel holds no T² buffer: its extra memory was at most 0.012 MB in all 139 cells of the probe sdpa. This is the reason for D8. In bf16 the SDPA kernel is slower at large T: 35 TFLOP/s against 57 TFLOP/s in fp16 at T = 9,221.
  • Batch size. A small batch does not fill the GPU at a small input resolution. ViT-S/16 at 224 px gives 416 img/s at batch size 1 and 1,077 img/s at batch size 32 (eager, bf16-cast, probe batch-knee). ViT-H+/16 at 512 px is flat within 10 % from batch size 1 to 16.
  • Compile and the RoPE form. In the eager forward pass, the element-wise chains take about 48 % of the block time at P2. mx.compile fuses each chain into one kernel. Slice and concatenate do not fuse, so the RoPE rotation of Step 5 stays at 4 kernels for each of q and k. The concat-free rotation moves the sign of rotate_half into the sin table and gives one fused kernel.
  • Quantized weights. The affine format stores each block weight as an 8-bit or 4-bit integer with one scale and one offset for each group of 64 weights. 8 bits pass the threshold sets of the dtype modes in the probes; 4 bits fail in every row. On this Mac the quantized matmul does not win at the token counts of DINOv3: quantized weights save memory, not time.

3.3 Build step 1: run rules and drivers

3.3.1 The GPU lock (F14)

In Step 5, light jobs of other agents overlapped timing runs. The wait loop of Section 13 of specs/05-all-sizes/verify.html protected only the agent that ran it. Step 6 makes the rule code that every entry point runs.

  • heavy_job(label, timeout_s=None) is a context manager with three actions. (1) It writes its process id into the registry LOCK_REGISTRY (~/.cache/dinov3-apple/gpu-lock.d/). The entry marks a lock-aware process. (2) It takes an exclusive fcntl.flock on LOCK_PATH (~/.cache/dinov3-apple/gpu.lock, outside the repo, shared by all worktrees). The flock sets the order of the lock-aware jobs. (3) While it holds the flock, it waits until other_heavy_jobs() finds no process outside the lock. It polls every 20 s in both waits and writes one log line for each wait.
  • A process outside the lock is a process whose command line matches HEAVY_JOB_PATTERN and that is not a registered process, an ancestor or a child of a registered process, the own process or one of its ancestors. A registry entry of a process that no longer runs counts as absent.
  • The reason for this order: a process that waits inside heavy_job also matches HEAVY_JOB_PATTERN, and so does its uv run parent. If each waiter waited for all other matching processes before it took the flock, two waiters would wait for each other for ever. With the flock first and the registry, two waiters enter one after the other (T5).
  • With timeout_s, a wait that takes longer than timeout_s raises GpuLockTimeoutError. The command line has the option --timeout (R54, T7).
  • HEAVY_JOB_PATTERN is the pattern of the Step 5 wait loop plus [d]inov3_apple\.gpu_lock: [b]in/pytest|[s]cripts/bench|[c]ross_check\.py|[m]ake_reference\.py|[p]rofile_block\.py|[d]inov3_apple\.gpu_lock. other_heavy_jobs leaves out its own process and all its ancestors (for example the uv run process), and the registered processes with their ancestors and children.
  • The holder writes its process id into the environment variable DINOV3_GPU_LOCK. Its child processes inherit it and enter at once. So a pytest session that starts a driver in a subprocess, or a driver that starts its workers, does not wait for itself.
  • macOS releases a flock when its process ends. So a crash leaves no stale lock.
  • Entry points: tests/conftest.py (from pytest_sessionstart to pytest_sessionfinish), and main of bench_speed.py, bench_mlx_port.py, benchmark.py, cross_check.py, make_reference.py and profile_block.py. The lock is in main, not in the run functions; T8 calls main(argv) of each script with a fake worker runner and checks the two conftest hooks. A dry run takes no lock.
  • Light GPU work outside these entry points, for example a probe or a one-line check, runs through the command line: uv run python -m dinov3_apple.gpu_lock -- <command>. It waits, takes the lock, runs the command and returns its exit code.
  • The lock log goes to ~/.cache/dinov3-apple/gpu-lock.log: label, process id, the start of the wait, the start of the hold and the end (T6). The Verify agent reads it (AC19).
  • The lock cannot stop a job outside the lock that starts during a hold. So the driver records it: before and after each worker, bench_speed.py calls other_heavy_jobs() and writes the result into the field other_heavy_jobs_seen of the line (Table 8, T9). AC19 asks for an empty list in each timed line.

3.4 Build step 2: the compiled forward pass and the concat-free RoPE (D1 to D4, D6)

  • Order inside the step. 2a adds compile_backbone with the RoPE form of Step 5 and measures the change ratio C1 (eager against compiled). 2b adds the concat-free rotation to the eager and the compiled forward pass and measures C2 (compiled Step 5 form against compiled concat-free form) and C3 (autocast / cast). So each change has its own ratio.
  • MlxBackbone.forward_with_rope(pixels, cos2, sin2) holds the forward pass with the RoPE tables as arguments. MlxBackbone.__call__(pixels), the eager forward pass, reads the tables of the patch grid from the cache and calls it. So the eager and the compiled forward pass share one code path.
  • compile_backbone(model) returns a function forward(pixels). It reads the tables in Python, outside the trace, and calls mx.compile(lambda p, c, s: model.forward_with_rope(p, c, s), inputs=model.state). The weights are implicit inputs, so the output follows a later weight change (R35). The tables are explicit inputs. There is one trace for each input shape (B, H, W). No shapeless (it fails: "Slice cannot infer output shapes").
  • The RoPE cache leaves the module tree (R43). Today _rope_cache is a dict, and mlx.nn.Module keeps a dict attribute in its tree: the probes found it in model.state. Then each new patch grid changes the compiled inputs. Step 6 keeps the tables in a RopeCache, a plain Python object, which stays out of the tree (checked on the CPU). This differs from the probe form (mx.compile(lambda p: model(p), inputs=model.state)) only in how the tables enter the trace; the arithmetic is the same. T34 and W1 check bit equality, T37 counts the traces, and C2 measures the speed.
  • apply_rope(x, cos2, sin2) computes x · cos + (x2, x1) · (−sin1, sin2) on a (B, heads, T, 2, head_dim / 2) view, in fp32, then casts back to the dtype of x. rope_layout(cos, sin) turns the tables of rope_tables into cos2 and the signed sin2, each (T, 2, head_dim / 2), fp32. rope_tables does not change (ADR 0006). In IEEE arithmetic (−x2) · s equals x2 · (−s), so the result is bit for bit the Step 5 result (9 of 9 CPU cases and 360 of 360 GPU rows in the probes). The kernel reads a view with a negative stride (R48); T38 asserts bit equality in all three dtypes.
  • run_mlx(model, pixels, dtype_mode, forward=None). With forward, it runs the compiled forward pass of the model. Without it, it runs the eager forward pass (part tests and diagnostics). The parity tests of Step 5 (test_parity, test_batch_consistency) pass the compiled forward pass of the backbone slot. The worker test T56 runs the compiled forward pass of a small model. run_mlx_hidden_states, run_mlx_token_range and the stored-state tests W1 to W4 and W7, W8 of Step 5 stay eager.
  • Who holds the compiled function (R36). A function stored on the model forms a reference cycle that keeps the weights until gc.collect(). So only the caller holds it: the backbone slot holds the pair (model, forward) and free() drops the function first, then the model, then calls gc.collect() and mx.clear_cache(). The fixture mlx_forward(model) returns the function of the slot and raises ValueError for a model outside the slot. Scripts and the API of Step 7 never store it on the model.
  • Compile after the last weight change (R35). compile_backbone runs after the load and after nn.quantize. load_mlx_backbone returns a model with all weights set, so a caller compiles after the load.
  • CPU stream (R37). On the CPU stream, compiled and eager differ by up to 2.0e-6 (probe). T34 and T38 take a device parameter (gpu, cpu) and run the CPU case under mx.stream(mx.cpu), so each default session runs both devices. Only the backbone slot of the gated weights reads DINOV3_MLX_DEVICE; the small-model tests do not. On the CPU stream T34 uses a tolerance of 1e-5 (5 times the measured value); on the GPU it asserts bit equality. T38 asserts bit equality on both devices.
  • D3 and D6. No code change. The 2 casts after the layer norms stay. The projections stay separate, so q_proj and v_proj keep their names for the LoRA of Step 8a.

3.5 Build step 3: the quantized loader (D14 to D18, F1)

load_mlx_backbone(model_size, dtype_mode, tf32=False, ratio=LOAD_RATIO, bits=None, group_size=GROUP_SIZE) does these actions, in this order. With bits=None it does the Step 5 load, plus the placeholders of action 8.

  1. Call check_run_rule(model_size, matmul dtype size, label). ViT-7B/16 in fp32 raises RunRuleError before any file read.
  2. With bits: the dtype mode must be fp16-autocast or bf16-autocast (D15 option C), else ValueError. fp32 scales cost up to 6 times the dense time (D15 option E), and no decision covers the cast modes. bits must be in QUANTIZED_BITS (8, 4).
  3. The TF32 check of the fp32 dtype mode, as today.
  4. The need: required_mlx_load_bytes(model_size, dtype_mode, ratio, bits) = 1.2 × the weight bytes + 4 GB. With bits, the weight bytes are quantized_weight_bytes (Table 9). Then the memory check and mx.set_memory_limit(need).
  5. Build the skeleton MlxBackbone(config, dtype_mode). Its random weights stay lazy.
  6. With bits: nn.quantize(model, class_predicate=block_linear_predicate(bits, group_size)). The predicate returns {"group_size": 64, "bits": bits} for an nn.Linear whose path starts with layer., and False for the patch embedding (D16). mlx 0.32.4 accepts a dict from the predicate (read from nn.quantize).
  7. linear = linear_parameter_names(model): the weight and bias of each nn.Linear, and the weight, scales and biases of each nn.QuantizedLinear, plus its bias where the module has one (F1: QuantizedLinear is not a subclass of nn.Linear). quantized = quantized_weight_names(model): the .weight of each QuantizedLinear.
  8. placeholder_skeleton(model) replaces each parameter by mx.broadcast_to(mx.zeros((), dtype), shape) (R50). The shapes and the names stay, so the strict load checks the same things. An evaluated placeholder holds one value (4 bytes for the (8192, 8192) case). So an mx.eval of the skeleton, by mistake, cannot make the random fp32 weights of the whole model real (about 27 GB for ViT-7B/16, against ADR 0008). The lazy random weights of nn.Linear and of QuantizedLinear.__init__ lose their last reference and are never computed.
  9. Read every *.safetensors file with mx.load (lazy). Read the active memory and call mx.reset_peak_memory().
  10. For each pair of mlx_weights(tensors, dtypes, linear): the loader casts the array to the matmul dtype. If its key is in quantized: mx.quantize(array, group_size, bits) gives the packed uint32 weight, the scales and the offsets in the matmul dtype; evaluate all three and keep the pairs .weight, .scales, .biases. Else evaluate the array and keep the pair.
  11. model.load_weights(pairs, strict=True), then delete the pairs and call mx.clear_cache().
  12. Make the LoadReport with the field bits and write one load-peak line with the label "{model size} mlx {dtype mode} {bits}-bit".

3.6 Build step 4: preprocessing in MLX and the fp16 output (D12, D13)

  • resize_weights(n_in, n_out) gives the (n_out, n_in) fp64 weights of the bilinear antialiased resize of torch (upsample_bilinear2d_aa): a triangle filter whose support grows with the scale when the image shrinks. Each row sums to 1. functools.cache keeps the result for each size pair.
  • preprocess_frames(frames, size) takes uint8 RGB frames (B, h, w, 3) on the host and gives normalized fp32 pixels (B, 3, H, W) on the GPU. Steps: cast to fp32 and divide by 255; resize the rows (H, h) and the columns (w, W) with two fp32 matmuls; subtract IMAGENET_MEAN_VALUES and divide by IMAGENET_STD_VALUES. A cache keeps the fp32 matrices of each size pair as MLX arrays.

3.11 Build step 9: the paired speedup runs at P1 and P2 (D7, D21, F2)

  • Each run: 5 rounds × 5 dtype modes × 2 backends = 50 workers for each priority configuration. The order of the two alternates from round to round, and the order of the dtype modes rotates by one from round to round.
  • Two runs at different times (F2): run 1 (job J11) after the P1 profile (J9) and its fix, if any (J10), and before the matrix, so both runs measure the final code; run 2 (job J19) after the matrix, at least 2 h after the end of run 1.
  • For each dtype and output: the mode on each side by ADR 0004 (the fastest valid mode by the median over all rounds of both runs). Then one paired ratio for each round: mlx / torch-mps of these two modes. The run median of each run, the pooled median of all 10 ratios, and the spread between runs. For an even number of values the median is the lower of the two middle values (ADR 0004). This rule applies to the mode choice over the 10 rounds and to the pooled median of the 10 ratios.
  • The verdict of D21 (option b): "above 1" only if the pooled median and both run medians are above 1.

3.19 Words for GLOSSARY.md

These terms settle when the user approves this plan. On the approval, the agent adds them to GLOSSARY.md at once, before the build starts (Section 7 of explore.html, with changes).

  • Eager forward pass: the forward pass of the MLX backbone without mx.compile. Each call builds the graph again.
  • Compiled forward pass: the forward pass of the MLX backbone from compile_backbone: one mx.compile function with the weights as inputs (inputs=model.state) and the RoPE tables as arguments. It has one trace for each input shape.
  • Trace: the record of the operations of one call of a compiled function for one set of input shapes and dtypes. mx.compile makes it at the first call and replays it at later calls.
  • Fused kernel: one GPU kernel that mx.compile makes from a chain of element-wise operations.
  • Fusion barrier: an operation that mx.compile does not fuse with its neighbours, for example mx.fast.layer_norm, a matmul, slice and concatenate.
  • Concat-free rotation: the RoPE rotation x · cos2 + reversed(x) · sin2 on a (…, 2, head_dim / 2) view, with the sign of rotate_half in the sin table. It gives one fused kernel.
  • RoPE cache: the RoPE tables of each patch grid of one backbone, in the layout of the concat-free rotation (RopeCache). It is outside the module tree.
  • Change ratio: the throughput after a change divided by the throughput before it, both forms in one process, in alternation and in a rotated order. The median over the rounds. A change that compares two configurations (C3, C5) runs each configuration in its own subprocess, in alternation.
  • NAX kernel: an MLX Metal kernel that uses the Neural Accelerators. Its name contains "nax", for example steel_attention_nax.
  • Neural Accelerators on / off: the state with and without the NAX kernels. MLX_METAL_GPU_ARCH=applegpu_g16s turns the NAX kernels off.
  • Relaxed precision: the option of the NAX matrix operation that lets the hardware compute with less precision. MLX 0.32.4 turns it on in the NAX matmul and attention kernels.
  • Quantized weights: the weights of an nn.Linear module stored as 8-bit or 4-bit integers, with one scale and one offset for each group of weights (affine format). The scales and the offsets have the matmul dtype. A quantized row keeps the name of its dtype mode and adds the field bits.
  • Group size: the number of weights of one row that share one scale and one offset. Step 6 uses 64.
  • Placeholder skeleton: the backbone before a load, with a zero-stride placeholder for each parameter. An evaluation of it allocates one value for each parameter.
  • Preprocessing: the steps from an RGB image to the normalized fp32 pixels: divide by 255, resize (bilinear, antialiased), normalize with the ImageNet mean and standard deviation.
  • Separable resize: a resize as two matmuls with fixed weight matrices, one for the rows and one for the columns.
  • Best batch size: the batch size with the highest throughput for one model size, input resolution and dtype mode.
  • Paired group: the workers of one model size, input resolution and batch size in one matrix run: the torch-mps workers and the mlx workers, one after the other, in a rotated order.
  • Compile check: the comparison of a compiled torch-mps row with the Step 3 eager row of the same configuration and dtype mode. A compiled row below the eager row gets a follow-up group with both.
  • Speedup table: the table with the speedup of each configuration of the benchmark matrix (results/speedup-table.md).
  • Inside the noise: the mark of a paired ratio within 1 ± 0.03, the spread inside one arm in the probe paired-noise.
  • Spread between runs: (largest run median − smallest run median) / smallest run median, over two or more runs of the same configuration at different times.
  • MLX peak: mx.get_peak_memory() after mx.reset_peak_memory(): the largest MLX allocation during one measured phase. It is not the peak memory (the lifetime maximum of the process footprint).
  • Load footprint peak: the lifetime maximum of the process footprint after a model load (the field load_footprint_peak_bytes). It is not the load peak.
  • Fault bound: a loose parity bound that catches only faults, for example a wrong input cast. It is not a threshold.
  • Heavy job: a job that loads a model, runs a benchmark or trains. One heavy job runs at a time (CLAUDE.md, run rules).
  • GPU lock: the exclusive file lock that each heavy job and each light GPU job takes before it starts (heavy_job). Its holder also waits for jobs that do not use the lock.
  • Compile row (changed): a benchmark result with the backbone wrapped by torch.compile on torch-mps or by mx.compile on mlx. Since Step 6, every configuration has compile rows (ADR 0009).
  • Speedup (changed): the throughput of mlx divided by the throughput of the baseline row, from a paired run (ADR 0009). At P1 and P2 the median of the paired ratios of two runs.
  • Priority configuration (changed): one of the two configurations that the benchmarks measure in two paired runs of five rounds, and where each change gets its change ratio: P1 (ViT-S/16, 224 px, batch size 8, frame embedding) and P2 (ViT-H+/16, 512 px, batch size 8, patch embeddings).

def rope_layout(cos: np.ndarray, sin: np.ndarray) -> tuple[np.ndarray, np.ndarray]:
    """Return the RoPE tables in the layout of the concat-free rotation (D2).

    Args:
        cos: The cos table of rope_tables, (T, head_dim), fp32.
        sin: The sin table of rope_tables, (T, head_dim), fp32.

    Returns:
        cos2 and sin2, each (T, 2, head_dim / 2), fp32. sin2 holds -sin in its first half: the
        sign of rotate_half moves into the table, so the rotation needs no join.
    """
    t, head_dim = cos.shape
    half = head_dim // 2
    signed = np.concatenate([-sin[:, :half], sin[:, half:]], axis=-1)
    return cos.reshape(t, 2, half), signed.reshape(t, 2, half)


def apply_rope(x: mx.array, cos2: mx.array, sin2: mx.array) -> mx.array:
    """Rotate queries or keys with the RoPE tables, without a join (D2, option R2).

    out = x * cos + (x2, x1) * (-sin1, sin2). The pair (x2, x1) is a reversed view of an axis of
    size 2, so mx.compile fuses the rotation into one kernel. The rotation runs in fp32 and the
    result has the dtype of x, as in Step 5. In IEEE arithmetic (-x2) * s equals x2 * (-s), so the
    result equals the Step 5 form bit for bit.

    Args:
        x: Queries or keys, (B, heads, T, head_dim).
        cos2: The cos table, (T, 2, head_dim / 2), fp32.
        sin2: The signed sin table, (T, 2, head_dim / 2), fp32.

    Returns:
        The rotated values with the shape and the dtype of x.
    """
    b, h, t, d = x.shape
    xr = x.reshape(b, h, t, 2, d // 2).astype(mx.float32)
    out = xr * cos2 + xr[..., ::-1, :] * sin2
    return out.astype(x.dtype).reshape(b, h, t, d)


class RopeCache:
    """The RoPE tables of each patch grid, in the layout of apply_rope (plan action A3).

    A plain object, not a dict: mlx.nn.Module keeps a dict attribute in its module tree, so
    model.state and the inputs of the compiled forward pass would change with each new grid (R43).
    """

    def __init__(self, head_dim: int, theta: float) -> None:
        self.head_dim = head_dim
        self.theta = theta
        self._tables: dict[tuple[int, int], tuple[mx.array, mx.array]] = {}

    def tables(self, grid_h: int, grid_w: int) -> tuple[mx.array, mx.array]:
        """Return (cos2, sin2) of one patch grid. The first call computes them in NumPy."""
        key = (grid_h, grid_w)
        if key not in self._tables:
            cos, sin = rope_tables(grid_h, grid_w, self.head_dim, self.theta)
            self._tables[key] = tuple(mx.array(table) for table in rope_layout(cos, sin))
        return self._tables[key]

    def __len__(self) -> int:
        return len(self._tables)

    def __call__(self, pixels: mx.array) -> mx.array:
        """The eager forward pass: the tables of the patch grid from the RoPE cache."""
        p = self.config.patch_size
        return self.forward_with_rope(pixels, *self.rope(pixels.shape[2] // p, pixels.shape[3] // p))


def compile_backbone(model: MlxBackbone) -> Callable[[mx.array], mx.array]:
    """Return the compiled forward pass of one backbone (D1, ADR 0010).

    One trace for each input shape (B, H, W). The weights enter as implicit inputs
    (inputs=model.state), so the output follows a later weight change (R35). The RoPE tables enter
    as arguments. Call it after the last weight change (the load, nn.quantize). The caller holds
    the function: a function stored on the model keeps the weights until gc.collect() (R36).

    Args:
        model: A loaded backbone.

    Returns:
        forward(pixels) -> tokens, with the contract of model(pixels).
    """
    traced = mx.compile(lambda p, c, s: model.forward_with_rope(p, c, s), inputs=model.state)
    patch = model.config.patch_size

    def forward(pixels: mx.array) -> mx.array:
        cos2, sin2 = model.rope(pixels.shape[2] // patch, pixels.shape[3] // patch)
        return traced(pixels, cos2, sin2)

    return forward


def run_mlx(
    model: MlxBackbone,
    pixels: np.ndarray,
    dtype_mode: str,
    forward: Callable[[mx.array], mx.array] | None = None,
) -> np.ndarray:
    """Run the backbone on stored pixels and return all tokens after the final layer norm, fp32.

    Args:
        model: A backbone from load_mlx_backbone.
        pixels: Normalized fp32 pixels, (B, 3, H, W).
        dtype_mode: A key of MLX_DTYPE_MODES. It must be the dtype mode of the model.
        forward: The compiled forward pass of model, from compile_backbone (D4). None runs the
            eager forward pass (part tests, diagnostics).

    Raises:
        ValueError: If dtype_mode is not the dtype mode of the model.
    """
    if dtype_mode != model.dtype_mode:
        raise ValueError(f"the model runs in {model.dtype_mode}, not in {dtype_mode}")
    tokens = (forward or model)(mx.array(pixels)).astype(mx.float32)
    mx.eval(tokens)
    return np.array(tokens)


def mlx_embeddings(
    tokens: mx.array, dtype_mode: str, patch_fp32: bool = False
) -> tuple[np.ndarray, np.ndarray]:
    """Return the frame embeddings and the patch embeddings of one batch on the host (D13).

    The frame embeddings are fp32. In the four fp16 and bf16 dtype modes the patch embeddings are
    fp16: half the host bytes for at most 3e-8 of parity (probe fp16-output). NumPy has no bf16,
    so the bf16 modes cast to fp16 on the GPU; after the final layer norm no value is above 18.

    Args:
        tokens: All tokens after the final layer norm, (B, 5 + N, D).
        dtype_mode: The dtype mode of the backbone.
        patch_fp32: True for fp32 patch embeddings in every dtype mode.

    Returns:
        The frame embeddings (B, D) and the patch embeddings (B, N, D).
    """
    half = MLX_DTYPE_MODES[dtype_mode].matmul != mx.float32
    frame = tokens[:, 0].astype(mx.float32)
    patches = tokens[:, NUM_PREFIX_TOKENS:].astype(
        mx.float16 if half and not patch_fp32 else mx.float32
    )
    mx.eval(frame, patches)
    return np.array(frame), np.array(patches)

@cache
def resize_weights(n_in: int, n_out: int) -> np.ndarray:
    """Return the (n_out, n_in) fp64 weights of the bilinear antialiased resize of torch (D12).

    The rule of upsample_bilinear2d_aa: a triangle filter whose support grows with the scale when
    the image shrinks. Each row sums to 1.
    """
    scale = n_in / n_out
    support = max(scale, 1.0)
    weights = np.zeros((n_out, n_in))
    for i in range(n_out):
        center = scale * (i + 0.5)
        lo = max(int(center - support + 0.5), 0)
        hi = min(int(center + support + 0.5), n_in)
        taps = np.maximum(0.0, 1.0 - np.abs((np.arange(lo, hi) - center + 0.5) / support))
        weights[i, lo:hi] = taps / taps.sum()
    return weights


def preprocess_frames(frames: np.ndarray, size: tuple[int, int]) -> mx.array:
    """Return normalized fp32 pixels (B, 3, H, W) from uint8 RGB frames (B, h, w, 3) (D12).

    The steps of preprocess.preprocess on the GPU: divide by 255, resize the rows and the columns
    with two matmuls, normalize with the ImageNet mean and standard deviation. The uint8 frames go
    to the GPU: a quarter of the fp32 bytes.

    Raises:
        TF32ModeError: If TF32 is on: the resize matmuls run in fp32 (ADR 0005).
    """
    if tf32_enabled():
        raise TF32ModeError("set MLX_ENABLE_TF32=0: the resize matmuls run in fp32")
    _, h, w, _ = frames.shape
    rows, columns = _resize_matrices(h, w, size)  # cached fp32 MLX arrays, (H, h) and (w, W)
    x = mx.array(frames).astype(mx.float32).transpose(0, 3, 1, 2) / 255.0
    x = rows @ x @ columns
    mean = mx.array(IMAGENET_MEAN_VALUES).reshape(1, 3, 1, 1)
    std = mx.array(IMAGENET_STD_VALUES).reshape(1, 3, 1, 1)
    return (x - mean) / std

class GpuLockTimeoutError(TimeoutError):
    """A wait for the GPU lock took longer than its time limit."""


@contextmanager
def heavy_job(
    label: str,
    poll_s: float = 20.0,
    lock_path: Path = LOCK_PATH,
    registry: Path = LOCK_REGISTRY,
    pattern: str = HEAVY_JOB_PATTERN,
    timeout_s: float | None = None,
) -> Iterator[None]:
    """Hold the GPU lock, then wait until no GPU job outside the lock runs (F14).

    The flock comes first: it sets the order of the lock-aware jobs. A lock-aware process writes
    its process id into the registry before it waits, and other_heavy_jobs leaves out each
    registered process with its ancestors and children. So two waiters never wait for each other.
    A child of the holder (LOCK_ENV set) runs at once. macOS releases a flock when its process ends.

    Raises:
        GpuLockTimeoutError: If a wait takes longer than timeout_s.
    """
    if os.environ.get(LOCK_ENV):
        yield
        return
    registry.mkdir(parents=True, exist_ok=True)
    entry = registry / str(os.getpid())
    entry.write_text(label)
    start = time.monotonic()
    try:
        with lock_path.open("a") as file:
            while not _try_flock(file):  # fcntl.LOCK_EX | fcntl.LOCK_NB
                _wait_or_raise(label, ["the holder of the GPU lock"], start, poll_s, timeout_s)
            while others := other_heavy_jobs(pattern, registry):  # jobs outside the lock
                _wait_or_raise(label, others, start, poll_s, timeout_s)
            _log_lock(label, "hold")  # gpu-lock.log: label, process id, event, time
            os.environ[LOCK_ENV] = str(os.getpid())
            try:
                yield
            finally:
                del os.environ[LOCK_ENV]
                fcntl.flock(file, fcntl.LOCK_UN)
                _log_lock(label, "end")
    finally:
        entry.unlink(missing_ok=True)

def _lower_median(values: list[float]) -> float:
    """Return the median; for an even count, the lower of the two middle values (ADR 0004)."""
    ordered = sorted(values)
    return ordered[(len(ordered) - 1) // 2]


def pass_verdict(run_medians: list[float], pooled_median: float) -> str:
    """Return the verdict of a speedup at P1 or P2 (D21, option b).

    "above 1" only if the pooled median of all paired ratios and the median of each run are above
    1. Two runs that disagree in sign give "not above 1". The caller computes both medians with
    _lower_median.

    above = pooled_median > 1 and all(median > 1 for median in run_medians)
    return "above 1" if above else "not above 1"

    verdict = "above 1" if ratio > 1 else "not above 1"
    return f"{verdict}, inside the noise" if abs(ratio - 1) <= NOISE else verdict

7 Benchmarks

All benchmarks run through scripts/bench_speed.py, after the GPU lock, on AC power, one worker at a time, each in its own subprocess after its memory check. The time budget of each worker is that of Step 3: warm-up at least 3 batches and 2 s; timed batches at least 30 batches and 10 s, stop at 60 s once 10 batches are done. One worker gives the frame time and the patch time (Table 4 of the Step 3 plan). The worker time limit is 900 s for mlx and 3,600 s for torch-mps (the compile of ViT-7B/16 is not measured).
