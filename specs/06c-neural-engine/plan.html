1 Goal

Step 6c converts the Hugging Face backbone of ViT-S/16 to ViT-H+/16 into Core ML packages that run on the Apple Neural Engine with fp16 parity. It measures them on the Neural Engine (coreml-ne), on the GPU (coreml-gpu) and with ALL (coreml-all), against our compiled mlx in paired runs. It measures the two-stream run: Core ML on the Neural Engine and compiled mlx on the GPU at the same time. The result answers one question: can the Neural Engine add throughput to the GPU, which Step 6 found at its matmul limit?

The explore probes found the obstacle and its fix. The attention scores of DINOv3 reach 2.5 million (36 times the largest fp16 value), and the Neural Engine stores them in fp16, so the plain fp16 export breaks (finding F1). The Neural Engine rewrite (Section 3.2) keeps every value inside fp16 and is exact in real numbers.

2 DINOv3 topic

How the Neural Engine runs the attention and the feed-forward network, and the numeric range of DINOv3 in fp16: the attention scores, the residual stream with its register tokens, LayerScale and the feed-forward branch. The Learn stage writes docs/learn/06c-neural-engine.html: Figure 1 of explore.html, the range table (Table 3 of explore.html plus the build data), the compute plan of one block, the annotated code of ne_attention and rewrite_for_neural_engine, and the surprises (F1, the subnormal weights of the LayerScale fold, ALL runs on the GPU only, batch size 8 slower than batch size 1 on the Neural Engine).

3.2 The Neural Engine rewrite

The rewrite changes the Hugging Face backbone in torch before the trace. It is exact in real numbers, so in fp32 on torch-cpu the rewritten backbone gives the output of the Hugging Face backbone (T1).

  1. Score scaling (s = 256). The attention function ne_attention computes z = (q · (1/√d) / s) · kᵀ, then softmax(clip(z − max z, −60,000 / s) · s). It is registered with transformers.AttentionInterface under the name "coreml-ne", and the rewrite sets config._attn_implementation to it.
  2. Residual-stream scale r. The wrapper divides the embeddings by r; the weights and the bias of o_proj and down_proj are multiplied by 1/r. LayerScale stays a separate multiplication. The ε of each layer norm becomes ε / r², so each layer norm gives exactly its old output on the scaled tokens. r is a power of two, so the products are exact except below the smallest normal fp16 value (6.1e-5).
  3. No LayerScale fold. The probe p7 to p10 fold of LayerScale into the weights made 94 % of the o_proj weights of block 1 of ViT-S/16 subnormal in fp16 (63 to 78 % in ViT-L/16 and ViT-H+/16; LayerScale factors down to 3.6e-8). It broke the parity on the Neural Engine and on the GPU (P2 patch 1st percentile 0.985). The build must not fold.

residual_scale(model_size) returns the smallest power of two r with (largest token value) / r ≤ 32,768. The largest token value comes from Table 1 of results/token-range-mlx.md (fp32 rows): r = 1 for ViT-S/16 (1,748), ViT-S+/16 (5,274), ViT-B/16 (14,926); r = 8 for ViT-L/16 (158,433) and ViT-H+/16 (149,750). The function reads the table, so a new token-range table changes r. ViT-7B/16 raises RunRuleError (D6).

3.4 The Core ML worker

A worker process (bench_coreml.py coreml-worker) runs one package on one compute unit. It records the first load time (the Neural Engine compile; Core ML caches it), unloads, loads again and records the cached load time. It runs the first output, checks the parity against the reference output with bench.check_validity(..., "fp16-cast"), then warms up and times the batches with the time budgets WARM_UP and TIMED of bench.py. Its result line has the fields of a Step 6 line where they apply (status, valid, finite, parity, frame and patch summaries, peak memory, versions, start time) plus the fields of Table 3.

3.5 Paired runs and the matrix

One paired group is one model size, input resolution and batch size: the workers coreml-ne, coreml-gpu and mlx in a rotated order (ADR 0004). The mlx worker runs the fastest valid fp16 dtype mode of the Step 6 matrix for the configuration (fp16-cast for ViT-S/16 to ViT-B/16; fp16-autocast for ViT-L/16 and ViT-H+/16, except fp16-cast at P2, as in results/speedup-table.md). The ratio of each Core ML side is its throughput divided by the mlx throughput of the same round. coreml-all joins only P1 and P2 at batch size 8.

Batch size 8 on the Neural Engine (amendment, F4). At batch size 8 the Neural Engine computes the patch embedding wrong (input tokens of block 1 with cosine 0.133). So a coreml-ne row at batch size 8 runs the batch-size-1 package with model.predict([{"pixels": x_i} for x_i in batch]), the batch API of Core ML; its line has "ne_batch_form": "batch-api". The batch-size-8 packages serve coreml-gpu and coreml-all. One extra J4 worker runs the ViT-S/16 batch-size-8 package on CPU_AND_NE at P1 as F4 evidence (expected: valid false). The Neural Engine side of the two-stream run (Section 3.6) uses the same rule.

3.6 The two-stream run

bench_coreml.py streams starts two worker processes: a Core ML worker on CPU_AND_NE and an mlx worker with the compiled forward pass. Each loads and warms up, then writes a ready file and waits. When both files exist, the parent writes a start time 2 s ahead. Each worker counts its batches from the start time for 10 s and reports its throughput. The cases of one round: ne alone, mlx alone, both. The order rotates over 3 rounds. The mlx side runs the batch size of the configuration; the Neural Engine side runs the faster of batch size 1 and 8 of the same model size and input resolution in the matrix (probe: 540 against 452 img/s at 224 px). The stream ratio is (Neural Engine + mlx, both) / (mlx alone), with the median over the rounds. The probe gave 2,458 against 2,040 img/s at P1 (1.20).

5 Key code

SCORE_SCALE = 256.0  # a power of two: the division adds no rounding error


def ne_attention(module, query, key, value, attention_mask, scaling=None, dropout=0.0, **kwargs):
    """Attention whose scores fit fp16 on the Neural Engine. Exact in real numbers:
    softmax(z) = softmax((z / s - max(z / s)) * s)."""
    s = SCORE_SCALE
    z = torch.matmul(query * (scaling / s), key.transpose(2, 3))  # at most 9,877 for ViT-S/16
    z = z - z.amax(-1, keepdim=True)                               # every value at most 0
    probs = torch.softmax(torch.clamp(z, min=-60000.0 / s) * s, dim=-1)
    return torch.matmul(probs, value).transpose(1, 2).contiguous(), None
def rewrite_for_neural_engine(model: DINOv3ViTModel, residual_scale: int) -> torch.nn.Module:
    """Return a module pixels -> tokens whose values fit fp16 (Section 3.2). No LayerScale fold."""
    model.config._attn_implementation = "coreml-ne"   # every layer shares this config
    with torch.no_grad():
        for layer in model.model.layer:
            for proj in (layer.attention.o_proj, layer.mlp.down_proj):
                proj.weight.mul_(1.0 / residual_scale)
                if proj.bias is not None:
                    proj.bias.mul_(1.0 / residual_scale)
    return NeuralEngineBackbone(model, residual_scale)  # embeddings / r, blocks, final layer norm

    of uv.lock) refuses this: "only 0-dimensional arrays can be converted to Python scalars".
    Remove this function when a coremltools release after 9.0 fixes _cast.
    """
    x = torch_ops._get_inputs(context, node, expected=1)[0]

        res = x if isinstance(x.val, dtype) else mb.const(val=dtype(value), name=node.name)

def patch_coremltools_cast() -> None:
    """Point coremltools' torch frontend at _cast_with_item, once, at run time.

    The installed coremltools files do not change. Raises CoremltoolsVersionError for a
    coremltools version other than 9.0, so a new release gets a fresh check.
    """
    if coremltools.__version__ != "9.0":
        raise CoremltoolsVersionError(coremltools.__version__)
    torch_ops._cast = _cast_with_item  # _int and _bool look _cast up in the module at each call

6 Tests

Write each test first and see it go red. tests/test_coreml.py starts with pytest.importorskip("coremltools"). T1 to T5, T9 and T13 use synthetic tensors or the small model of tests/small_model.py in torch only, and run in the default session (target: at most 5 s together; the default session stays at or below 60 s). Every test that converts or loads a Core ML package (T6 to T8, T10 to T12) runs only in the slow session (DINOV3_SLOW=1), as in tests/test_prior_art.py.

  1. test_ne_attention_equals_eager_in_fp32 (T1): synthetic q, k, v (B 2, 3 heads, 41 tokens, head dimension 64) with scores up to 1e7; ne_attention against eager_attention_forward in fp64: largest relative difference ≤ 1e-6.
  2. test_ne_attention_fp16_stays_finite (T2, F1): the same tensors in fp16 on torch-cpu: eager attention gives a non-finite value (red part of the evidence); ne_attention gives finite values with cosine ≥ 0.999 against fp64.
  3. test_rewrite_is_exact_in_fp32 (T3): the small models vits16 and vits16plus with r = 1 and r = 8, rewritten against the Hugging Face model on torch-cpu fp32: tokens equal within 1e-6 relative (with ε / r² the rewrite is exact up to fp32 rounding).
  4. test_rewrite_keeps_layer_scale (T4): after the rewrite each block still has layer_scale1 and layer_scale2 with the original factors, and o_proj.weight equals the original / r bit for bit (r a power of two).
  5. test_residual_scale_from_token_range (T5): r = 1, 1, 1, 8, 8 for ViT-S/16 to ViT-H+/16 from results/token-range-mlx.md; ViT-7B/16 raises RunRuleError; a table with a largest value of 70,000 gives 4.
  6. test_cast_patch_converts_with_numpy_2_5 (T6, slow): convert the small model vits16 at 32 px, batch size 1. Without the patch: TypeError (red). With it: a package with the input pixels and the output tokens.
  7. test_small_package_parity_on_each_unit (T7, slow): the T6 package on CPU_AND_NE, CPU_AND_GPU and ALL against the small model on torch-cpu fp32: cosine ≥ 0.999 (frame) and finite.
  8. test_compute_plan_report (T8, slow): the report of the T6 package: device counts sum to the number of non-constant ops; the cost shares sum to 1 ± 1e-6; the list of ops off the Neural Engine has name, op type and cost.
  9. test_package_path_and_line_fields (T9): the package name holds slug, side, batch size, s, r and the coremltools version; a fake worker line has the fields of Table 3; a broken first output (frame 0.035) gives valid false (risk R53); the stream schedule rotates the three cases over 3 rounds.
  10. test_plain_graph_fails_on_neural_engine (T10, slow, F1 evidence): the plain ViT-S/16 package at 224 px on CPU_AND_NE: frame cosine below 0.5 for iss-kibo-lab; on CPU_AND_GPU ≥ 0.999.
  11. test_vits16_package_passes_on_neural_engine (T11, slow): the rewritten ViT-S/16 package at 224 px batch size 1 on CPU_AND_NE: the fp16 thresholds of ADR 0003 for the 3 test images.
  12. test_convert_refuses_vit7b16_before_load (T12, slow only because it reads the config): convert_backbone("ViT-7B/16", 224, 1) raises RunRuleError before any weight read.
  13. test_patch_coremltools_cast (T13, default session): patch_coremltools_cast() sets coremltools.converters.mil.frontend.torch.ops._cast to _cast_with_item; a second call changes nothing; with a faked version "9.1" it raises CoremltoolsVersionError and leaves _cast as it was; the installed file ops.py has the same SHA-256 before and after the test; _cast_with_item gives the value 3 for a constant np.array([3]) where the original raises TypeError (red).
