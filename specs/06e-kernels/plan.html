Step 6e Kernels: Plan

Roadmap step 6e. Status: approved by the user on 2026-11-11. The approval is also the yes to the source build of C1 (Q1 of Section 9). Date: 2026-11-11.

Option picked in explore.html: "A, then C1" (the user, 2026-11-11).

1 Goal

Step 6e makes the compute-bound parts of a block faster, or shows with numbers that the current form is the best one. Part A joins the projections that read the same input into one matmul: q, k and v, and gate and up. A paired run at P1 and P2 decides whether the compiled path uses the joined form. Part C1 is a probe: a source build of MLX outside the repo measures whether other tile sizes close the gap of the 1,280 → 1,280 matmul, the bf16 1,280 → 10,240 matmul and the attention kernel. Our package keeps the released MLX.

2 DINOv3 topic

The shapes of the matmuls of one block, and how the shape of a matmul changes its rate on the M5 Max. The Learn stage extends docs/learn/06-5-roofline.html with a section on the joined projections and the tile sizes.

3 Design

3.1 Decisions

No.QuestionDecisionReason
D1Where do the joined weights live?Nowhere. The forward pass joins them with mx.concatenate inside the trace, at each call.The parameter names, the strict load, set_dtype and nn.quantize stay as they are. The weights stay implicit inputs of the trace, so a later weight change reaches the output (R35). No second copy of 1.15 GB. The cost of the concat: 1.15 GB of reads and writes for each batch at P2, about 2.2 ms at the memory roof, against a batch time of 388 ms (0.6 %). The paired run includes this cost.
D2How does the port select the form?Two plain attributes, not parameters: Attention.joined and SwiGLU.joined. The function set_joined_projections(model, qkv=..., ff=...) sets them on each block. Call it before compile_backbone.The same pattern as dtypes: nn.quantize and load_weights do not see a plain attribute. A trace reads the flag when it records, so the eager and the compiled forward pass keep one code path (ADR 0010).
D3The missing k_proj biasThe joined qkv matmul adds a bias of zeros for k when q or v have a bias. The joined form uses mx.addmm, as nn.Linear does.ViT-H+/16 has a bias on q_proj and v_proj, not on k_proj. Zero plus a value gives the same value, so the outputs stay equal.
D4Quantized weightsset_joined_projections raises ValueError for a model with nn.QuantizedLinear blocks.Packed weights, scales and offsets would need their own join. Quantized weights save memory, not time (ADR 0011).
D5EqualityThe joined form must give the same tokens bit for bit as the separate form. The C7 worker checks the first batch (R56). If a configuration is not bit equal, the worker records the largest difference, and the parity tests of ADR 0003 decide for that configuration.D6 of Step 6 measured bit-equal outputs at 224 px. At 512 px the matmul kernel can pick another tile size for the wider matrix.
D6The defaultFor each dtype mode and each of the two joins (qkv, ff): on if the pooled median of two runs at P2 is ≥ 1.03, and the median of each run is above 1 (pass rule D21 of Step 6); else off. An ADR records the defaults, because they reverse D6 of Step 6.Q4 of explore.html. A gain inside the noise does not change the code path of all users.
D7The C1 setupA clone of the MLX repo at tag v0.32.4 in ~/.cache/dinov3-mlx/mlx-src/, its own venv, a build from source. Our worker runs there with python -I and imports no module of the repo (ADR 0013). The repo gets numbers only.The same rules as the prior-art ports of Step 6b. The build changes no file of pyproject.toml or uv.lock.
D8The C1 sweepFirst a control: the unchanged source build against the wheel. Then, for each of three targets, at most 12 tile configurations, one build for each.A build that is slower than the wheel would make every ratio wrong. 12 builds for each target keep the sweep below about 3 hours.

3.2 Part A

  • A1: Attention.qkv and SwiGLU.hidden get the joined form (Section 5). The MLP model sizes have no gate, so only the qkv join applies to them.
  • A2: the change C7 measures four forms in one process: R (separate, the Step 6 form), R-J (both joins), R-Jqkv (only qkv) and R-Jff (only gate and up). So each join gets its own ratio in each dtype mode.

3.3 Part C1

  • C1a Control: the wheel and the unchanged source build run the same probe: the six linear shapes of scripts/probe_roofs.py and one SDPA shape (B = 8, 20 heads, T = 1,029, head dimension 64).
  • C1b Read: the build agent reads the dispatch code of the matmul and attention kernels of MLX 0.32.4 and lists the tile parameters and where MLX selects them. The plan does not name the files: the agent finds them and records them in the results.
  • C1c Sweep: three targets. T1: fp16 1,280 → 1,280 (o_proj, q, k, v), 43.0 TFLOP/s now. T2: bf16 1,280 → 10,240 (joined gate and up), 45.1 TFLOP/s now. T3: the attention kernel at the SDPA shape, 36.5 TFLOP/s now.
  • A gain of C1 goes into the results and into the explainer. A pull request to MLX is Q3 of explore.html: the user decides after C1 and sends it.

5 Key code

# src/dinov3_mlx/mlx_model.py, Attention (D1 to D3)
def qkv(self, x: mx.array) -> tuple[mx.array, mx.array, mx.array]:
    b, t, _ = x.shape
    if self.joined:
        weight = mx.concatenate([self.q_proj.weight, self.k_proj.weight, self.v_proj.weight])
        y = joined_linear(x, weight, self._qkv_bias())  # addmm; a zero k bias (D3)
        y = y.reshape(b, t, 3, self.heads, -1).transpose(2, 0, 3, 1, 4)
        return y[0], y[1], y[2]
    ...  # the separate form of Step 6, unchanged
# src/dinov3_mlx/mlx_model.py, SwiGLU (D1)
def hidden(self, x: mx.array) -> mx.array:
    if self.joined:
        weight = mx.concatenate([self.gate_proj.weight, self.up_proj.weight])
        gate, up = mx.split(joined_linear(x, weight, self._gate_up_bias()), 2, axis=-1)
        return self.activation(gate, up)
    return self.activation(self.gate_proj(x), self.up_proj(x))
# src/dinov3_mlx/mlx_model.py (D2, D4)
def set_joined_projections(model: MlxBackbone, qkv: bool, ff: bool) -> None:
    """Select the joined or the separate projections of each block. Call before compile_backbone."""
    if quantized_weight_names(model):
        raise ValueError("joined projections need unquantized block weights (D4)")
    for block in model.layer:
        block.attention.joined = qkv
        if isinstance(block.mlp, SwiGLU):
            block.mlp.joined = ff

6 Tests

Each test is written first and seen red. The tests T1 to T8 need no weights: they use the small models of tests/small_model.py.

  1. test_joined_qkv_equals_separate (T1): the small models vits16, vits16plus and vit7b16-shape give the same q, k and v bit for bit in both forms, in the five dtype modes. One case has a k_proj without a bias and a q_proj with a bias (D3).
  2. test_joined_gate_up_equals_separate (T2): SwiGLU.hidden is bit equal in both forms, in the five dtype modes.
  3. test_joined_forward_equals_separate (T3): the eager and the compiled forward pass give the same tokens bit for bit with set_joined_projections(model, True, True) and without it.
  4. test_joined_keeps_parameter_names (T4): model.parameters() has the same keys and shapes after set_joined_projections; load_weights(strict=True) still passes.
  5. test_joined_refuses_quantized_weights (T5): ValueError for a model after nn.quantize (D4).
  6. test_joined_follows_a_weight_change (T6): a compiled joined forward pass gives the new output after a weight change (R35).
  7. test_change_plan_c7 (T7): bench_speed.py change --change joined --dry-run lists C7 with the four forms at P1 and P2, in the dtype modes of Section 7.
  8. test_change_worker_ratio_of_each_form (T8): with four forms, the worker gives the ratio of each form to the first form in each round, and its median (stub forward functions, no GPU).
  9. test_probe_kernels_worker_imports (T9): the C1 worker file imports only mlx, numpy and the standard library, and calls no subprocess, pickle or torch (ADR 0013, as T12 of Step 6b).
  10. test_probe_kernels_driver_refuses (T10): the C1 driver refuses to run the source build without --allow-source-build, and refuses a worker path inside the source folder.
  11. test_kernels_table (T11): the table writer of C1 gives the ratio of each configuration to the wheel, and marks a configuration with cosine < 0.99999 as not valid (fixture lines).
  12. The parity tests of Steps 2 and 5 run unchanged. If D6 turns a join on by default, they run the joined form, because the compiled forward pass is the path of the parity tests (ADR 0010).

9 Open questions
