1 Summary

This page checks the 13 acceptance criteria of plan.html (Section 8, Table 3) against the code, the result lines, the lock log and the MLX source of the clone. The agent did not build the step. It changed no code and no result file. It ran ruff, the test session without weights and the two table writers, each through the GPU lock, after a memory check. It ran no model load, no benchmark and no build. It recomputed the key numbers from results/speed-joined.jsonl and results/kernels-c1.jsonl with its own scripts.

Result: 7 rows pass, 3 rows are partial, 1 row fails, 2 rows are open. Open: AC12 (rerun pending: the default session with weights) and AC13 (checked after Learn).

  • Part A is correct. The joined form gives the same tokens bit for bit as the separate form in all 20 B1 lines (60 of 60 form checks, largest difference 0.0). On the small models it is bit equal in 66 of 70 test cases. The 4 other cases (fp32, batch size 1, few tokens) differ by 1.9e-6 at most, because MLX takes another fp32 kernel for the separate matmul (AC1 partial).
  • The joins are slower everywhere. At P2 the pooled ratio to R is 0.940 to 0.997 in all 15 rows. No run median is above 1. D6 keeps all joins off, so no default changes (AC6 pass, AC8 has nothing to check).
  • The peak rule fails, with a low weight. R-J needs 125.5 to 546.1 MB more MLX peak than R at P2 (target ≤ 100 MB). Because the joins stay off, no default path pays this peak (AC7 fail).
  • The P1 rows read low. The bench harness switches the flags inside the timed batch. At P1, R-Jff runs the same graph as R and still reads 0.964 to 0.981 (V1, AC5 partial). The P2 decision does not change.
  • C1: the control holds, the sweep gain does not. The source build runs at the speed of the wheel (14 of 14 shapes within ± 1.7 %, AC9 pass). The best T1 and T2 ratios (1.015 and 1.036) come from a cold first round and a drift inside the T2 sweep, not from the tile sizes (V2, AC10 partial). The T3 gain (32,32,2,1: 1.022 to 1.045 in the warm rounds) needs a confirmation run. The T2 gap of the plan (45.1 TFLOP/s) does not exist: the wheel reaches 60.1 TFLOP/s (V3).
  • The three SDPA configurations with bk = 16 (cosine −0.2807) are a fault of the probe patch, not of MLX. The NAX attention kernel steps over the keys in pairs of 16-row fragments, so bk must be a multiple of 32. MLX ships only bk 32 and 64 (Section 5.3).
  • Findings. Section 8 gives 14 findings: 0 high, 3 medium, 11 low. Section 11 gives the commands of the reruns that the main session runs when the Mac is free.

4.1 The cost of the bench harness at P1 (V1)

The wrapper calls set_joined_projections before and after each call of the forward pass. time_batch_mlx starts its clock before this call (mlx_bench.py:93). So the timed batch includes the flag switch and the walk over all modules in quantized_weight_names. R has no wrapper.

5.3 The SDPA configurations with bk = 16

Three configurations give the same smallest row cosine −0.2807072: 64,16,4,1, 32,16,2,1 and 128,16,8,1. The agent read probe.patch and the MLX source of the clone. The fault is in the probe patch: it adds tile sizes that the NAX attention kernel does not support.

// mlx/backend/metal/kernels/steel/attn/kernels/steel_attention_nax.h (MLX 0.32.4)
constexpr short kU = 16;                        // line 138: one fragment is 16 rows
constexpr short TK = BK / kU;                   // line 152: bk = 16 gives TK = 1
for (short ik = 0; ik < TK; ik += 2) {          // line 221: two fragments per step
  NAXTile<T, 2, 1> Ktile;                       // line 229: loads 32 key rows
  ... mma(Stile.frag_at(iq, ik), Stile.frag_at(iq, ik + 1), ...)   // line 254
}
  • The kernel computes Q · Kᵀ for two 16-row key fragments in each step. With bk = 16 the score tile has one fragment (TK = 1), but the step writes frag_at(iq, 1): a fragment outside the tile, in thread memory. The result is wrong. All three configurations share bk = 16, so they give the same wrong values.
  • The kernel has static_assert checks for BQ, BD and BV (lines 141 and 150), but none for BK. So the build does not stop. A check BK % (2 * kU) == 0 would stop it.
  • MLX 0.32.4 instantiates the non-split kernel only with bk 32 and bk 64 (steel_attention_nax.metal, lines 23 to 29 before the patch), and sdpa_full_self_attention_nax selects bk = 32 (scaled_dot_product_attention.cpp:223). The released MLX never runs bk = 16. So this is not a fault of MLX as shipped. A missing static_assert is a small hardening for an upstream change, if the user wants one (Q3).
  • bk = 128 gives valid output but runs at 12.5 to 12.8 TFLOP/s (ratio about 0.30): the score tile of 8 fragments is too large for the registers.

7 Code check

  • _joined (mlx_model.py:356) joins the weights with mx.concatenate inside the trace at each call (D1). _joined_bias (:341) adds zeros of the weight dtype for a layer without a bias (D3) and gives None if no layer has a bias. joined_linear (:325) calls mx.addmm with a bias, else a matmul, as nn.Linear.
  • The joined qkv reshapes the output to (B, T, 3, H, hd) and transposes it to (3, B, H, T, hd); head h holds the same channels as in the separate form. T1 shows bit equality.
  • set_joined_projections (:601) sets plain attributes, so model.parameters() and the strict load do not change (T4). compile_backbone passes inputs=model.state, so the weights stay implicit inputs (T6).
  • change_forms gives each joined form its own compile_backbone. The trace records on the first call inside _JoinedForm, so each form keeps its graph. R records first, with the flags off. The wrapper also runs on each timed call (V1).
  • run_forms resets the MLX peak before the timed batches of each form and keeps the largest peak of the rounds (B2). first_batch_check compares the full first batch; the C7 branch records the differences and the validity and does not stop (D5).
  • The C1 driver refuses the source build without --allow-source-build and refuses a worker file inside the source folder (T10). build_info checks that venv-build imports mlx from the source folder. worker_env removes the overrides and sets MLX_ENABLE_TF32=0; the worker removes the overrides again at start.
  • The worker measures each configuration with 3 warm-up calls and the median of 20 calls (V2). Its NumPy checks use float32 on the same rounded inputs; the cosine threshold 0.99999 holds for all valid rows (smallest 0.9999985 in bf16).
