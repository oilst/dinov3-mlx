1 Goal

Step 6d fixes the concat fault of the Neural Engine (finding V1 of Step 6c). The Neural Engine writes a wrong token concat when the concat has two or more constant inputs. The Hugging Face embeddings concat the CLS token and the register tokens as two constants. The rewrite version ne3 concats one constant prefix of 5 rows with the patch tokens. It is exact. The probes of explore.html (Table 5) show fp16 parity on CPU_AND_NE with it for ViT-S/16, ViT-L/16 and ViT-H+/16 at 224 to 512 px.

The step converts the 25 packages of Step 6c again with ne3, and repeats the Step 6c jobs: parity on the three compute units, the compute plan, the matrix, the paired runs and the two-stream run. A guard in the conversion and two tests keep the fault out of every future package.

2 DINOv3 topic

The token sequence of DINOv3: the CLS token and the 4 register tokens (the prefix tokens, learned parameters) in front of the patch tokens of the patch embedding. RoPE does not rotate the prefix tokens, so the order of the sequence matters.

The Learn stage extends docs/learn/06c-neural-engine.html with one section: Figure 1 of explore.html (the token map), the E6 table of the concat forms, the annotated code of ne_embeddings and constant_concats, and the surprises (the fault is not an fp16 range fault; the 224 px packages passed only because the compute plan put the concat on the CPU).

3.2 Packages and disk

The 25 packages of Step 6c with the rewrite: 15 at batch size 1 (5 model sizes × 224, 448, 512 px) and 10 at batch size 8 (224 and 512 px). The name changes from …-ne2-s256-r… to …-ne3-s256-r…. Only the compiled model stays on disk (Step 6c rule). ViT-7B/16 stays deferred.

Disk. Free disk now: about 18 GB. The 25 ne3 packages need about 12 GB. Each new package and process adds bundles to the Core ML bundle cache ~/Library/Caches/python/com.apple.e5rt.e5bundlecache (about 6 GB during the 16 probe loads of explore.html).

  1. Before J1, the build deletes the 25 ne2 compiled packages (about 12 GB): ne3 replaces them, and on CPU_AND_NE they give wrong tokens. The ne2 result lines stay. The user approved this delete with the plan on 2026-11-08.
  2. Each job starts with a disk check. Below 10 GB free, the job does not start; the build stops and reports. A worker that cannot run writes the status "skipped: disk".
  3. The build does not touch the bundle cache and ~/.cache/dinov3-apple/coreml/probes (Q4 of explore.html, open for the user).

4 Data flow

5 Key code

def ne_embeddings(embeddings: DINOv3ViTEmbeddings, pixels: torch.Tensor) -> torch.Tensor:
    """The tokens (B, 5 + N, D) of DINOv3ViTEmbeddings.forward, with one constant prefix.

    The Neural Engine writes a wrong concat when the concat has two or more constant inputs
    (the concat fault, Step 6d). The CLS token and the register tokens go in as one constant
    of 5 rows. In fp32 the output is bit-equal to the Hugging Face embeddings.
    """
    patches = embeddings.patch_embeddings(pixels).flatten(2).transpose(1, 2)  # (B, N, D)
    prefix = torch.cat([embeddings.cls_token, embeddings.register_tokens], dim=1)  # (1, 5, D)
    return torch.cat([prefix.expand(pixels.shape[0], -1, -1), patches], dim=1)
def constant_concats(mlmodel: Any) -> list[str]:
    """Return the names of the concat ops with two or more constant inputs (the concat fault)."""
    names = []
    for op in mlmodel._mil_program.functions["main"].operations:
        if op.op_type == "concat":
            constants = [v for v in op.values if v.op is not None and v.op.op_type == "const"]
            if len(constants) >= 2:
                names.append(op.name)
    return names

The build checks the MIL access of constant_concats against coremltools 9.0 first (T15 red step: the ne2 graph of the small model must give one name). A constant can also come as a value with val set and no producing op; the function counts both.

6 Tests

Write each test first and see it go red. T14 runs in the default session (torch only, below 1 s). T15 to T17 convert or load a Core ML package, so they run in the slow session (DINOV3_SLOW=1), as in Step 6c. The default session stays at or below 60 s.

  1. test_ne_embeddings_equal_hugging_face (T14, default): the small models vits16 and vits16plus, batch size 1 and 2, 32 px and 64 px: ne_embeddings equals model.embeddings bit for bit (torch.equal). T3 (the whole rewrite exact in fp32, ≤ 1e-6 relative) stays green with ne3.
  2. test_constant_concats_finds_the_fault (T15, slow): convert the embeddings of the small model vits16 at 64 px two ways. The Hugging Face form gives exactly one name; the ne3 form gives none. convert_module on a module with the Hugging Face embeddings raises NeuralEngineGraphError and writes no package.
  3. test_embeddings_part_on_neural_engine (T16, slow): a package of the ne3 embeddings of ViT-S/16 at 448 px, batch size 1 (gated weights, about 1 MB), on CPU_AND_NE against torch-cpu fp32: 0 tokens with cosine below 0.999, and the compute plan puts the concat on the Neural Engine. This test finds a change of the fault in a new macOS or Core ML release. The Hugging Face form is reported in the test log only (probe E1: 788 wrong tokens), not asserted.
  4. test_vits16_448_package_passes_on_neural_engine (T17, slow): the J1 package vits16-448-b1-ne3-… on CPU_AND_NE: the fp16 thresholds of ADR 0003 for the 3 test images (with ne2: frame −0.0147, red).
  5. T9 (default): the package name holds ne3. T11 (slow): unchanged, now on the ne3 package.
