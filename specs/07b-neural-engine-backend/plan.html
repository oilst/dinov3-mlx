Step 7b Neural Engine backend: Plan

Roadmap step 7b. Status: draft. Date: 2026-11-15.

1 Goal

Step 7b adds the backend "mlx+ne" to Embedder. Compiled mlx runs on the GPU in the process of the user. Core ML runs on the Neural Engine in one worker process. A work queue gives each batch to the stream that is free, and the outputs come back in the order of the input frames. The backend gives the same outputs as "mlx", within the fp16 thresholds of ADR 0003. Through the public API, it reaches the stream ratio of Step 6d: 1.32 at P1 in the probe of explore.html. mlx stays the default backend, and the core of the package stays free of torch.

2 DINOv3 topic

How one workload is split between two accelerators, and what a fixed-shape package costs: the conversion time, the first load and the disk. The step writes the explainer docs/learn/07b-neural-engine-backend.html. It covers the work queue, the tail rule, the worker process and why two threads fail (Table 6 of explore.html: the stream ratio drops to 0.52).

3 Design

The user picked D1 A, D2 C, D3 B and D4 A in explore.html. The probe D2 C chose the worker process. This section gives the details.

3.1 The public API

  • Embedder(model_size, dtype_mode, batch_size, bits, backend="mlx+ne"). The signature, the methods and the outputs stay as in ADR 0019: frame embeddings (B, D) in fp32, patch embeddings (B, H/16, W/16, D) in fp16 in the half dtype modes.
  • New methods: close(), and __enter__ and __exit__, so with Embedder(...) as model: ends the worker. close() on the backend "mlx" does nothing.
  • The constructor checks these items before any weight look-up, in this order, with one specific error each:
    1. ViT-7B/16: ValueError. Step 6d made no package for it.
    2. dtype_mode="fp32": ValueError. The Neural Engine runs in fp16, so its frames cannot pass the fp32 thresholds. The four half dtype modes are valid: an fp16 frame also passes the bf16 thresholds.
    3. The Neural Engine extra is missing: NeuralEngineExtraError (a subclass of ImportError) with the command uv add "dinov3-mlx[ne]".
    4. macOS older than 15 (the deployment target of the packages): NeuralEngineExtraError.
  • bits=8 stays valid. It changes the mlx stream only; the Neural Engine stream runs the unquantized package.

3.2 The Core ML packages

  • One package for each model size and input resolution: the ne3 package of batch size 1 (ADR 0014, ADR 0016). The Neural Engine stream calls it with the batch API: one predict call with a list of batch_size inputs. In Step 6d the batch API was as fast as the package of batch size 8, or faster (P1: 666 against 494 img/s).
  • The cache stays ~/.cache/dinov3-mlx/coreml/ (ADR 0015). package_path takes (H, W). A square size keeps its old name, for example vits16-224-b1-ne3-s256-r1-ct9.0, so the 25 packages of Step 6d stay valid. A non-square size gets {H}x{W} in the name.
  • The first embed call with a new input resolution converts its package, if the cache does not hold it. The conversion runs in a subprocess, python -m dinov3_mlx.ne_convert, after a memory check with convert_need_bytes. So torch and transformers never load into the process of the user, and their memory goes back to the system when the conversion ends.
  • Step 6d costs at batch size 1 (Tables 1 and 2 of results/coreml-6d-table.md): conversion 2.7 s (ViT-S/16, 224 px) to 24 s (ViT-H+/16, 512 px), plus the model load; first load on the Neural Engine 1.7 to 16.9 s; cached load 0.04 to 0.09 s; disk 44 MB (ViT-S/16) to 1.7 GB (ViT-H+/16) for each package.

3.3 The worker process

  • The constructor starts the worker with subprocess.Popen([sys.executable, "-m", "dinov3_mlx.ne_worker"]). It does not use multiprocessing: its spawn start imports the __main__ module of the user again.
  • The worker imports only numpy and coremltools. It never imports torch or mlx.
  • Control messages are JSON lines on stdin and stdout: load, run, close, and the replies loaded, done and error. The pixels and the tokens go through shared memory: two slots, each with one input buffer and one output buffer.
  • The worker ends when its stdin closes. So it also ends when the process of the user dies.
  • Python 3.12 has no track=False for SharedMemory. The worker removes its buffers from the resource tracker after it attaches them, so its exit does not unlink the buffers of the parent. A test checks this.
  • A worker error, an exit or a reply timeout raises NeuralEngineError with the last 2,000 characters of the stderr of the worker. There is no silent fall-back to mlx.

3.4 The work queue and the tail rule

  • One scheduler loop in the main thread. It needs no second thread, so the GIL result of the probe does not apply.
  • The main thread preprocesses every batch on the GPU with preprocess_frames, so both streams see the same pixels. For the Neural Engine stream it copies the fp32 pixels into a free slot and sends run. The copy is 4.8 MB for each batch at P1 and 25 MB at P2.
  • The worker can hold two batches, one in each slot, so it does not wait while the main thread runs an mlx batch.
  • Tail rule: the worker takes the next batch only if (k + 1) × tne ≤ (q − 1) × tmlx. Here k is the number of batches that the worker holds, q the number of batches in the queue, and tne and tmlx the estimated seconds per batch of each stream. So the worker never finishes after the mlx stream would finish alone. A call with one batch runs on mlx only.
  • The estimates start from the warm-up batch of each stream for each input resolution. After each batch they move with an exponential average (weight 0.2).

3.5 Memory

  • The constructor checks the free memory for the mlx load plus the worker. In Step 6d the peak footprint of a Neural Engine process was 0.38 to 0.48 GB, so the plan adds 1 GB for the worker and its four buffers.
  • The conversion subprocess checks its own need, up to 5.0 GB for ViT-H+/16 at 512 px and batch size 1 (Table 1 of the Step 6d table), before it loads torch.

5.2 The scheduler loop (in src/dinov3_mlx/streams.py)

def run_queue(batches: list[Batch], mlx: MlxStream, ne: NeuralEngineStream, rates: Rates) -> list[Tokens]:
    """Give each batch to the free stream and return the tokens in the order of the batches."""
    queue = deque(range(len(batches)))
    tokens: list[Tokens | None] = [None] * len(batches)
    while queue or ne.held:
        while queue and ne.free_slot() and takes_next(ne.held, len(queue), rates):
            index = queue.popleft()
            ne.submit(index, batches[index])               # copy pixels to a slot, send "run"
        if queue:
            index = queue.popleft()
            tokens[index] = mlx.run(batches[index])        # mx.eval: the worker runs meanwhile
            rates.update("mlx", mlx.last_seconds)
        for index, result, seconds in ne.poll(block=not queue):
            tokens[index] = result
            rates.update("ne", seconds)
    return tokens


def takes_next(held: int, queued: int, rates: Rates) -> bool:
    """The tail rule: the worker finishes no later than the mlx stream alone would."""
    return (held + 1) * rates.ne <= (queued - 1) * rates.mlx

5.3 The worker loop (in src/dinov3_mlx/ne_worker.py)

def serve(model: Predictor, slots: list[Slot], read: Callable[[], dict | None], write: Callable[[dict], None]) -> None:
    """Run each "run" message with the batch API until "close" or the end of stdin."""
    while (message := read()) is not None and message["op"] != "close":
        slot = slots[message["slot"]]
        start = time.perf_counter()
        feed = [{"pixels": slot.pixels[i : i + 1]} for i in range(message["used"])]
        for i, result in enumerate(model.predict(feed)):
            slot.tokens[i] = result["tokens"][0]
        write({"op": "done", "slot": message["slot"], "seconds": time.perf_counter() - start})

The Neural Engine stream sends only the used frames of a padded last batch, so the worker does not run the zero frames.

6 Tests

Light tests load no model. They use fake streams and a fake predictor, and they run in the default session without weights.

  1. test_run_queue_keeps_the_order: 200 random calls with fake streams of random speed and random batch counts. The tokens of each batch come back at its index. Exact.
  2. test_tail_rule_one_batch_runs_on_mlx, test_tail_rule_slow_ne_takes_no_batch, test_tail_rule_equal_rates_share: the rule of Section 3.4 on fixed rates.
  3. test_rates_start_from_warm_up_and_move: the exponential average with weight 0.2.
  4. test_mlx_ne_refuses_vit7b, test_mlx_ne_refuses_fp32, test_mlx_ne_needs_the_extra, test_mlx_ne_needs_macos15: the error and its text, and no call of ensure_weights.
  5. test_package_path_square_keeps_the_name, test_package_path_non_square.
  6. test_serve_runs_the_used_frames, test_serve_ends_at_close_and_at_eof: the worker loop with a fake predictor.
  7. test_worker_exit_keeps_shared_memory: a real worker process with a fake predictor (a test switch of ne_worker) attaches the buffers and exits; the parent can still read them.
  8. test_worker_crash_raises: the fake predictor raises; the call raises NeuralEngineError with the stderr text.
  9. test_close_ends_the_worker: close() ends the worker within 2 s and unlinks the buffers. test_no_orphan_worker: after the session, no dinov3_mlx.ne_worker process is left.
  10. test_wheel_installs_without_torch (Step 7, extended): the wheel without the extra has no torch and no coremltools, and Embedder("ViT-S/16") on "mlx" works.

Tests with the weights and a package. The default session uses ViT-S/16; DINOV3_SLOW=1 adds ViT-S+/16 to ViT-H+/16.

  1. test_mlx_ne_parity: each frame passes the fp16 thresholds of ADR 0003 against the reference: frame ≥ 0.999, patch mean ≥ 0.999, patch 1st percentile ≥ 0.99. Input resolutions 224, 448 and 512 px, and one non-square size (224 × 320 px) for ViT-S/16. A test switch sends half of the batches to each stream, so both streams are tested.
  2. test_mlx_ne_equals_each_stream: the frames of the mlx stream equal the backend "mlx", and the frames of the Neural Engine stream equal the package alone. Largest difference 0.
  3. test_mlx_ne_padded_last_batch: 13 frames at batch size 8 give 13 rows, in order.

7 Benchmarks

A new option --streams of scripts/bench_api.py, with its own results file results/api-streams-7b.jsonl and table results/api-streams-7b-table.md. Each worker runs one Embedder in its own subprocess: "mlx" or "mlx+ne", in paired rounds that alternate the order. Both backends get the same frames, in the default dtype mode fp16-autocast at batch size 8. A warm-up call comes first, so the conversion and the first load are not in the timed calls. 9 New terms

  • Core ML worker: the process python -m dinov3_mlx.ne_worker that runs the Neural Engine stream of the backend "mlx+ne".
  • Tail rule: the Core ML worker takes the next batch of the work queue only if it finishes its batches no later than the mlx stream would finish the queue alone.
  • API stream ratio: the throughput of "mlx+ne" divided by the throughput of "mlx" in the same round, through the public API.

These terms go into GLOSSARY.md when the user approves the plan.

10 Open questions

  • Q1 (the user): the dtype modes. The plan refuses only fp32. The other choice is fp16-autocast only: one precision for all frames, but a smaller contract. Recommendation: refuse only fp32.
  • Q2 (the user): the time of the conversion. The plan converts at the first embed call with a new input resolution. The other choice is a constructor parameter sizes=[224, ...] that converts and loads at once, so no call is slow. Recommendation: the first call, plus a README note. A later version can add sizes.
  • Q3 (the user): the heavy benchmarks. P3 and P2 need a free Mac. The Build can finish with the light tests and P1. P3 and P2 then run on a free night, after your yes.
  • Q4 (the user): the cache size. One package for each model size and input resolution can fill many GB, and Core ML keeps its own bundle cache. The plan only documents the folder. A clean-up command is out of scope.
