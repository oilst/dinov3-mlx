# Roadmap

One row for each step. `docs/plan.html` describes each step in detail. A step gets its spec folder `specs/NN-slug/` when it starts.

| Step | Goal | DINOv3 topic that we learn | Spec folder | Status |
|---|---|---|---|---|
| 0 Workflow | Mission, roadmap, tech stack, glossary and the plan | The model family and the training method (overview) | none | done |
| 1 Scope | Prior art, repo license, Python project, access to the weights | What the other ports cover | `specs/01-scope/` | done (2026-11-06). All six model sizes are in the Hugging Face cache. |
| 2 Reference | Reference outputs and parity tests for all model sizes | Tokens and outputs: CLS token, register tokens, patch tokens | `specs/02-reference/` | done (2026-11-06). The ViT-7B/16 reference file is deferred: its memory check failed. |
| 3 Baseline | Benchmark harness and the PyTorch MPS baseline | Where the compute goes for each model size and input resolution | `specs/03-baseline/` | done (2026-11-07). Measured again on the 94 W adapter. AC5 (spread ≤ 5 %) fails in 5 of 10 rows: accepted by the user. ViT-7B/16 (B4) is deferred. ADR 0004. |
| 4 MLX port | ViT-S/16 in MLX and the weight converter | Each part of a block: patch embedding, RoPE, attention, LayerScale, feed-forward network | `specs/04-mlx-port/` | done (2026-11-07). ViT-S/16 in fp32 passes parity on 12 of 12 configurations (1 − 3.1e-11 or better). Paired ratio mlx / torch-mps (median of 3 rounds): 1.39 at batch size 8, 3.12 at batch size 1. ADR 0005 and 0006. |
| 5 All sizes | All model sizes in fp32, fp16 and bf16 | SwiGLU, model scaling, numeric range of the tokens | `specs/05-all-sizes/` | done (2026-11-07). Path D4-Y (the user's yes of 2026-11-07). On mlx, ViT-S/16 to ViT-H+/16 pass parity in 282 of 300 configurations (5 model sizes × 5 dtype modes × 12). The other 18 are the expected fp16 overflow of ViT-L/16 (12) and ViT-H+/16 (6) in fp16-cast, as on torch-mps. ViT-7B/16: the streamed fp32 reference holds the fp32 weights of one block at a time (peak 1.75 GB against a need of 4.82 GB; 26.86 GB for the whole model). It equals the five full-model reference files bit for bit (largest difference 0.0). Against it, the 48 mlx parity rows of ViT-7B/16 in the four fp16 and bf16 dtype modes pass, and the 24 torch-mps rows in fp16-cast and bf16-cast pass (largest share of a threshold budget: 43.9 %). The run rule refuses its 12 fp32 rows on mlx, and its 36 torch-mps rows in fp32, fp16-autocast and bf16-autocast (fp32 weights). Load peak of ViT-7B/16 in bf16: 13.5 GB. P2 paired ratio mlx / torch-mps: about 1 in the cast modes, 1.09 to 1.16 in fp32 and the autocast modes (both runs). AC13 is partial: the half SDPA kernel uses relaxed precision (F3). ADR 0007 and ADR 0008. |
| 6 Speed | Compiled graphs, batch sizes, input resolutions, quantized weights | Attention cost at high input resolution | `specs/06-speed/` | done (2026-11-08). Compiled forward pass on mlx, torch.compile rows on torch-mps, paired groups for every configuration. Paired verdicts mlx / torch-mps (pooled median of two runs, frame and patch output): P1 fp32 1.067 and 1.068 above 1; P1 fp16 0.867 and 0.900, bf16 0.878 and 0.881 not above 1; P2 fp32 1.092, fp16 1.032 and 1.033, bf16 1.013 (inside the noise) above 1. Matrix: 324 cells, 306 with a ratio: 140 above 1, 166 not above 1; 18 ViT-7B/16 fp32 cells empty (ADR 0008). Both backends reach the GPU matmul limit (about 29 TFLOPS at ViT-L/16), so mlx is at about the speed of torch.compile in the half dtypes. One paired round does not decide the cells near 1 (V17). Quantized weights: 8 bits valid in 72 of 72 rows, 4 bits not valid in 72 of 72 rows; 8 bits save memory, not time. Verify: 18 pass, 8 partial, 0 fail before the fixes; 20 pass, 8 partial after the Learn and Close stages. Deviations 1 and 2 wait for the user's confirmation. ADR 0009, 0010 and 0011. |
| 6b Prior-art comparison | Measure the related public repos (MLX ports of DINOv2 and DINOv3, Core ML exports, mlx-image) with our harness: frame throughput and parity at the same model size, input resolution and batch size | Which parts of the backbone each port changes, and what that costs in parity | `specs/06b-prior-art/` | done (2026-11-08), except the Python ports C1 and C2: their 8 rows are "blocked" until the user answers Q1 (ADR 0013). Core ML exports C7 to C9 against our compiled forward pass, two runs of 5 paired rounds (ADR 0012): FP32 exports slower than ours (prior-art ratio 1.05 to 1.09; 1.53 at P1 with batch size 8, where an export makes 8 calls); FP16 exports equal or faster (ViT-B/16 448 px 0.98 to 0.99, inside the noise; ViT-S/16 512 px 0.93 to 0.94; DINOv2 at 1374 tokens 0.85 to 0.87). Every DINOv3 export reproduces the reference output with float input; the 8-bit image input costs 0.001 of patch 1st percentile. Port changes in our code: the bf16 RoPE of C1 and C2 fails the fp32 thresholds (patch p01 0.99953 ViT-S/16, 0.99838 ViT-H+/16); the unfused attention costs 10 to 24 % of the throughput. Verify: 12 of 12 after the fixes. |
| 6c Neural Engine | Explore Core ML on the Apple Neural Engine, alone and in parallel with the GPU, against mlx | How the Neural Engine runs attention and the feed-forward network, and its numeric range in fp16 | `specs/06c-neural-engine/` | done (2026-11-08), except the Neural Engine fault (V1 of `verify.html`): a follow-up step for the user. The Neural Engine rewrite (score scale 256, residual-stream scale r with ε / r², ADR 0014) makes every model size from ViT-S/16 to ViT-H+/16 pass the fp16 thresholds on CPU_AND_GPU and ALL. On CPU_AND_NE only ViT-S/16 and ViT-S+/16 at 224 px pass (2 of 15 rows): the other packages give wrong tokens from the output of the embeddings on. Two-stream run at P1 with valid outputs: stream ratio 1.26 and 1.31 (2,503 img/s against 1,984 for mlx alone); at P2 below 1. Core ML on the GPU 0.62 to 1.15 times compiled mlx. Verify: 9 pass, 2 partial, 1 fail (AC4). |
