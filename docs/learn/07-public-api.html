1 Why this explainer

Steps 2 to 6 built the MLX port and measured it. A user of the package sees only one class: Embedder. This page shows what the class does with a frame, and why. It adds no new part of DINOv3. It connects the parts of the earlier explainers into one path.

import numpy as np
from dinov3_mlx import Embedder

model = Embedder("ViT-S/16")  # fp16-autocast, batch size 8
frames = np.stack(rgb_frames)  # uint8, (B, h, w, 3)
frame, patches = model.embed(frames, size=(224, 400))  # (B, 384) fp32, (B, 14, 25, 384) fp16

3 The constructor

# src/dinov3_mlx/api.py, Embedder.__init__ (shortened)
if bits is not None and (bits not in API_BITS or dtype_mode not in API_BITS[bits]):
    raise ValueError(...)  # only bits=8, only in the two autocast modes (ADR 0011)
self.model_size = model_size_of(model_size)  # "ViT-S/16" or "facebook/dinov3-vits16-…"
check_run_rule(self.model_size, MLX_DTYPE_MODES[dtype_mode].matmul.size, label)  # before any file read
if tf32_active():  # Section 5; before the weights, so no download for nothing
    raise TF32ModeError("… import dinov3_mlx before mlx, or set MLX_ENABLE_TF32=0 …")
ensure_weights(self.model_size)  # Hugging Face cache, else a download; WeightsAccessError
limit = mx.get_memory_limit()
try:
    self._model = load_mlx_backbone(self.model_size, dtype_mode, bits=bits)
finally:
    mx.set_memory_limit(limit)  # the loader sets the need of its load
self._forward = compile_backbone(self._model)  # ADR 0010: the path of the parity tests
  • The checks that need no file run first: the backend, the dtype mode, the batch size and bits. bits takes only None or 8, and 8 only in fp16-autocast and bf16-autocast: 4-bit weights do not pass the parity thresholds in any of the 72 rows of Step 6 (ADR 0011).
  • model_size_of(name) accepts the model size name or its Hugging Face id, and raises ValueError for another name.
  • check_run_rule stops ViT-7B/16 in fp32 before any file read. Its fp32 weights alone need about 27 GB (ADR 0008).
  • ensure_weights(model_size) (hub.py) returns the weight folder. If the weights are missing, it downloads them. If the Hub refuses, because the DINOv3 License is not accepted or no token is set, it raises WeightsAccessError with the model page and hf auth login. The download happens only when the user calls the constructor.
  • load_mlx_backbone sets an MLX memory limit for its load. That limit stays for the whole process. So the constructor sets the old limit again, also when the load fails.
  • compile_backbone gives the compiled forward pass. The parity tests use the same function (ADR 0010), so the API output is the tested output.

4 The package import

# src/dinov3_mlx/__init__.py (shortened)
os.environ.setdefault("MLX_ENABLE_TF32", "0")  # before the first use of mlx (ADR 0005)

def __getattr__(name: str) -> object:  # PEP 562: a public name loads on first use
    return getattr(import_module(_MODULES[name]), name)
  • import dinov3_mlx sets MLX_ENABLE_TF32=0 if the variable is not set. An explicit value of the user stays.
  • The import loads no mlx and no torch. Embedder and the four error classes load on first use. So a torch process can import a module of the package and gets no mlx, and the API path never imports torch. The core needs five packages: mlx, numpy, safetensors, huggingface-hub and pillow.

5 The TF32 probe

TF32 keeps 10 bits of the mantissa of an fp32 value in a matmul. MLX turns it on by default. The fp32 dtype mode and the resize matmuls of the preprocessing need it off (ADR 0005). MLX reads MLX_ENABLE_TF32 once, at its first use. A process that used mlx before import dinov3_mlx can run TF32 while the variable now says 0. So the variable alone does not tell the truth, and the constructor measures it.

# src/dinov3_mlx/mlx_model.py
def tf32_active() -> bool:
    steps = np.arange(64 * 64, dtype=np.float32).reshape(64, 64) % 1000
    values = (1.0 + steps * 2.0**-20).astype(np.float32)  # needs 20 mantissa bits
    product = mx.matmul(mx.eye(64, dtype=mx.float32), mx.array(values), stream=mx.gpu)
    return not np.array_equal(np.array(product), values)  # TF32 rounds them to 1

The identity matmul gives the values back exactly in fp32. With TF32 each value 1 + k · 2−20 loses its low bits. One 64 × 64 matmul costs below 10 ms.

6 The preprocessing contract

The API does the work of the Hugging Face image processor of DINOv3, on the GPU (06-4):

  1. The uint8 frames go to the GPU: a quarter of the bytes of fp32.
  2. Divide by 255.
  3. Resize to the input resolution (H, W): bilinear, with antialiasing, on float values. Two fp32 matmuls, one for the rows and one for the columns. The resize does not keep the aspect ratio. The default 224 gives 224 × 224 px, as the Hugging Face default.
  4. Subtract the ImageNet mean and divide by the ImageNet standard deviation.

as_uint8_batch(frames) accepts a uint8 array (B, h, w, 3), or a list of PIL images or uint8 arrays of one size. Another dtype raises TypeError, so float frames cannot enter with another scale. Frames of different sizes raise ValueError. input_resolution(size) accepts an int or (H, W); each side must be a multiple of 16, the patch size.

7 The batch loop and the padded last batch

# src/dinov3_mlx/api.py, Embedder._run (shortened)
for start in range(0, len(batch), self.batch_size):
    chunk = batch[start : start + self.batch_size]
    used = len(chunk)
    if used < self.batch_size:  # zero frames: the compiled shape stays the same
        chunk = np.concatenate([chunk, np.zeros((self.batch_size - used, *chunk.shape[1:]), np.uint8)])
    tokens = self._forward(preprocess_frames(chunk, (height, width)))
    frame = tokens[:used, 0].astype(mx.float32)  # the rows of the zero frames go
    patches = tokens[:used, NUM_PREFIX_TOKENS:].astype(dtype).reshape(used, *grid, -1)
    mx.eval(frame, patches)  # one batch at a time keeps the graph and the memory small
  • mx.compile records one trace for each input shape. A last batch of 5 frames would need a second trace. The zero frames keep one shape, so each input resolution needs one trace only.
  • A frame in a batch does not see the other frames: attention runs inside one frame. So the zero frames do not change the outputs of the real frames. Test T3 checks this: 5 frames at batch size 8 against batch size 5, cosine at least 0.99999.
  • The padded rows cost time. B1 measured the API against the direct path: P1 0.996 and P2 1.009 with full batches, but P1-pad (13 frames, so 3 zero frames) only 0.819 (results/api-table.md). Call the API with a multiple of batch_size frames, or set batch_size to the number of frames.

8 The token split

After the final layer norm the backbone gives 1 CLS token, 4 register tokens and N = (H/16) · (W/16) patch tokens (02).

  • Frame embedding: token 0, the CLS token, as fp32, shape (B, D). The API does not L2-normalize it. A classifier that needs unit length divides by the norm itself.
  • Patch embeddings: tokens 5 to 5 + N − 1, as (B, H/16, W/16, D). They are fp16 in the four fp16 and bf16 dtype modes (patch_dtype), fp32 in fp32 or with patch_fp32=True.
  • The register tokens are in no output.
  • embed gives both from one forward pass. embed_frames and embed_patches give one. as_numpy=False keeps the outputs on the GPU as mx.array.

Table 1. The five dtype modes. Throughput: Table 5 of results/speedup-table.md (compiled mlx, frame output, one round). Parity: the worst value over all model sizes and 12 configurations, Table 1 of results/parity-mlx.md.

  • fp16-autocast is the only fast dtype mode that gives finite outputs for all six model sizes and passes the fp16 thresholds of ADR 0003. It keeps the residual stream and the layer norms in fp32, so the large token values of ViT-L/16 and ViT-H+/16 do not overflow (05-3).
  • fp16-cast overflows for ViT-L/16 and ViT-H+/16. bf16-cast is about 12 % faster at ViT-S/16, but its patch embeddings have a lower parity.
  • fp32 is half as fast and cannot run ViT-7B/16.

11 Surprises

  • An environment variable is not the state. MLX reads MLX_ENABLE_TF32 once. Only a measurement shows if TF32 is on in the running process.
  • The memory limit of one load stays for the whole process. A library must set the limit of its caller again.
  • Three zero frames out of 16 rows cost 18 % of the throughput (P1-pad). The cost of a fixed trace shape is real at small batch sizes.
  • A lazy import is part of the contract. Without it, a torch process that imports one helper of the package loads mlx too.
